# Catalog batch H: recipe and first-run feasibility

Checked 2026-09-29. The shared contract subsequently added `no-account` onboarding, allowing a scoped VictoriaMetrics single-node recipe and read-only first-run verifier. The remaining entries still need their own deployment and acceptance decisions; a fabricated admin password would misrepresent readiness.

| App | Result and next prerequisite | Primary source |
| --- | --- | --- |
| Traefik | Blocked: Docker-provider sample mounts the Docker socket and its sample dashboard is explicitly insecure. Needs an approved non-socket provider/configuration, entrypoint and TLS ownership, and an accountless onboarding contract. | [Traefik Docker quick start](https://doc.traefik.io/traefik/getting-started/docker/) |
| Transmission | Blocked: upstream headless daemon guidance does not establish an upstream-published Compose image; image choice and VPN fail-closed design need separate provenance and acceptance. | [Transmission headless usage](https://github.com/transmission/transmission/blob/main/docs/Headless-Usage.md), [upstream image request](https://github.com/transmission/transmission/discussions/6071) |
| Umami | Blocked: official installation seeds `admin`/`umami` and instructs immediate password change. A source-backed, checkpointable headless password-change/login contract is needed before a recipe can safely expose this service. | [Umami installation](https://docs.umami.is/docs/install) |
| Unbound | Blocked: resolver configuration, forwarding policy, and host DNS/port ownership are user choices; no first-admin account exists for the current schema. | [Unbound documentation](https://unbound.docs.nlnetlabs.nl/) |
| UniFi Controller | Blocked: deployment topology, device-adoption reachability, and first-account behavior require an explicitly selected distribution and official contract. The app's catalog source points to network product guidance rather than an image/version. | [UniFi Network help](https://help.ui.com/hc/en-us/categories/6583256751383-UniFi-Network) |
| Valkey | Blocked: official pinned container can be identified, but it is an accountless datastore. Needs a secret-safe authentication and accountless onboarding schema before deployment. | [Valkey 8.1.3 release](https://valkey.io/download/releases/v8-1-3/) |
| Vaultwarden | Blocked: upstream Compose example requires a selected HTTPS `DOMAIN` and persistent `/data`; first-account creation must be paired with approved TLS and registration closure. Current schema's manual first-admin password file alone cannot enforce the generated password. | [Vaultwarden upstream README](https://github.com/dani-garcia/vaultwarden/blob/main/README.md) |
| Vector | Blocked: official image is available, but a functional deployment requires a selected source/sink config file. No first-admin account exists for the current schema. | [Vector Docker installation](https://vector.dev/docs/setup/installation/platforms/docker/) |
| VictoriaMetrics | Implemented pinned `v1.153.0` single-node private recipe with the documented data path and self-scrape flag. The setup adapter reads `/health` and `/api/v1/status/buildinfo`, requiring HTTP 200, a successful status, and exact version. This verifies readiness/version only; external ingestion, retention policy, and restart persistence remain unverified. | [VictoriaMetrics quick start](https://docs.victoriametrics.com/victoriametrics/quick-start/), [single-node health semantics](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/), [documented build-info route](https://docs.victoriametrics.com/guides/grafana-vmauth-openid-configuration/) |
| WUD | Blocked: Docker inventory access implies Docker socket or a separately owned proxy boundary; do not add a casual socket mount. Need a reviewed least-privilege route and notification/monitor choices. | [WUD documentation](https://getwud.github.io/wud/) |
| ZeroTier | Blocked: joining a network requires an externally supplied network ID, authorization, and host networking privileges. Those choices and gates are not represented by the current recipe contract. | [ZeroTier documentation](https://docs.zerotier.com/) |

The unimplemented entries are contract or scope blockers, not claims that the upstream applications cannot run headlessly. No Docker, live service, or broad test was run.

Focused validation: the VictoriaMetrics setup module bundled successfully with Bun. Catalog-wide validation could not finish because concurrent, unrelated `ollama` and `stirling-pdf` manifests currently use an unsupported image-status value; VictoriaMetrics no longer appears in the validator errors.
