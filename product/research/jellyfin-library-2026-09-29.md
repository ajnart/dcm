# Jellyfin library setup for Seerr 3.5.0

## Pin and requirement

The catalog recipe pins `ghcr.io/jellyfin/jellyfin:12.1.20260915-010956` (not `latest`); its adapter accepts the upstream-reported `12.1.*` version line and records the server ID. The recipe mounts the owner-approved media root read-only at `/data` and explicitly requires owner-selected library directories plus a readback. Seerr v3.5.0 exposes Jellyfin libraries as `{id, name, enabled}` and a library-sync endpoint; creating Jellyfin libraries is prerequisite state, but does not configure Seerr's server connection or enable its library selections. ## Minimal HTTP sequence

Run only against the exact running Jellyfin app project and its saved loopback origin. Require the owner to select paths under `/data`; each selected path must already exist inside the container. Jellyfin v12.1 rejects missing directories. The single-path catalog convention can be `/data/media/movies` and `/data/media/tv` (the root harness's current mapping), but the reusable recipe must not assume those subdirectories exist or choose them without owner input. The current [`SetupContext`](../../.agents/skills/self-host/workflows/selfhost/references/catalog/types/setup.ts#L54-L83) has no dedicated media-path field, so setup must preserve explicit path provenance through its existing input/persistence boundary rather than infer a host path.

1. Verify `/System/Info/Public` reports version `12.1.*`, a stable server ID, and completed startup. Authenticate the generated `admin` credential with `POST /Users/AuthenticateByName`; require the returned user to be `admin`, administrator policy true, and retain the access token only in memory. The current per-app adapter already performs these checks.
2. `GET /Library/VirtualFolders` with that admin session. For the canonical mappings, require exactly one `Movies` library with `CollectionType=movies` and the chosen movie location, and exactly one `Shows` library with `CollectionType=tvshows` and the chosen TV location. Jellyfin v12.1 defines those exact enum values and returns `Name`, `CollectionType`, and `Locations`.
3. For each absent library only, `POST /Library/VirtualFolders?name=Movies&collectionType=movies&paths=<encoded-path>&refreshLibrary=false` (and the analogous `Shows`/`tvshows` request). The body is optional; omitting it selects Jellyfin's default `LibraryOptions`. `refreshLibrary=false` is also Jellyfin's default and avoids requesting a full scan during setup. The API requires first-time-setup or elevated authorization and returns 204.
4. Read `/Library/VirtualFolders` again and require one exact match for each mapping; do not delete/recreate, rename, or silently adopt a same-name mismatch or extra location. If a temporary admin session was used, log it out. A separate Seerr step must sync the library list, select the returned IDs, and read back `enabled=true` for the chosen entries.

The library controller applies `FirstTimeSetupOrElevated`. In pinned v12.1,
the authorization handler assigns a recognized API-key principal the
Administrator role, which satisfies that policy after startup. This permits
the saved Jellyfin key to perform a later library readback without persisting
an admin session. The exact authorization-header parser was not independently
retrieved in this review, so fresh-instance verification remains necessary.

## Existing setup paths and replay boundary

[`bootstrap-jellyfin.ts`](../../scripts/bootstrap-jellyfin.ts#L5-L69) already has the desired harness mapping, pre-reads libraries, rejects duplicate/name/type/path conflicts, creates only missing entries with `refreshLibrary=false`, then reads back name/type/location. Its verifier uses `Locations.includes(path)`, so it permits unexpected extra locations; exact single-path equality is safer for the reusable owner-approved setup. It also uses the older startup wizard flow (`/Startup/Configuration` and `/Startup/RemoteAccess`); v12.1 still exposes those routes but marks them obsolete. The harness logs out in `finally`; the per-app adapter currently does not. [`jellyfin/setup.ts`](../../.agents/skills/self-host/workflows/selfhost/references/catalog/apps/jellyfin/setup.ts#L16-L18) instead uses the v12.1 first-user GET, one-time admin update, and one-time wizard completion, then verifies login and creates/readbacks one labeled API key. It currently returns `mediaLibrary: "not-configured-owner-path-required"`, and `inspect()` does not read libraries. [Startup controller](https://github.com/jellyfin/jellyfin/blob/v12.1/Jellyfin.Api/Controllers/StartupController.cs#L97-L155) · [adapter first-run/inspect](../../.agents/skills/self-host/workflows/selfhost/references/catalog/apps/jellyfin/setup.ts#L202-L218) · [session logout](../../scripts/bootstrap-jellyfin.ts#L63-L70)

The library POST is not safe to replay blindly: Jellyfin v12.1 checks whether the virtual-folder directory already exists and allocates a suffixed name (`Movies2`, etc.) on a duplicate create. The harness's read-before-write is idempotent for settled state, but has no durable checkpoint for a request whose outcome is unknown. The per-app adapter already persists a `beforeSendCheckpoint` for one-time startup/key writes, but its stage list has no library action. Add per-library attempt checkpoints before POST; after interruption, read the inventory and only mark success on an exact canonical match. If the attempt is recorded but that match is absent, duplicated, or mismatched, stop for inspection rather than POST again. Persist the selected non-secret paths with the server ID/project checkpoint, and make `inspect()` revalidate them; also update the setup record/ready contract so “configured” cannot mean only admin+key. The recipe's restart-acceptance gate should recheck the same mapping after restart.

No Docker/apply or live-service calls were made. The API sequence above was checked against the pinned Jellyfin v12.1 source and Seerr v3.5.0 first-party API specification.
