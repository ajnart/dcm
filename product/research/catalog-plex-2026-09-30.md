# Plex shared setup review — 2026-09-30

The [official Docker image tags](https://hub.docker.com/r/plexinc/pms-docker/tags/) list `plexinc/pms-docker:1.43.4.10903-e5521bd8c` for amd64, arm/v7, and arm64. The catalog now names that versioned tag, not the `latest`, `public`, or `beta` update-on-start variants. A versioned tag is still mutable at the registry; exact image digest must be resolved and approved at apply.

The [official Docker guide](https://github.com/plexinc/pms-docker/blob/master/README.md) documents bridge networking, TCP 32400, `/config`, `/transcode`, `/data`, `TZ`, `PLEX_CLAIM`, and optional `ADVERTISE_IP`. A safe shared Compose shape would publish only TCP 32400 on loopback, use an owned `/config` volume on a filesystem with working locks, and mount only the owner's approved media read-only. Discovery ports, LAN exposure, router forwarding, and remote access are separate decisions. Loopback-only publishing also means Plex clients elsewhere on the LAN are not yet served.

No `recipe.json` or `setup.ts` was added. The current recipe schema has no onboarding kind for an external Plex account, and the shared owner can only generate private files, not accept a short-lived claim token from the owner at exact apply. Pretending `PLEX_CLAIM` is a generated admin password would claim the wrong account; omitting it starts an unclaimed server. The [official image contract](https://github.com/plexinc/pms-docker/blob/master/README.md) says the claim token is used only on first run to obtain a server token and is ignored after sign-in. Neither container liveness nor HTTP 200 proves that the intended account owns the server. A server token must remain private and is not automatically a separately created API key.

A deterministic no-browser route needs a private, owner-supplied claim-token handoff with expiry/replay handling; a one-time Compose environment injection that does not disclose it in plans, logs, or handoff; and an authenticated, owner-bound readback after claim and restart. Those contracts belong to shared setup, not a Plex-only workaround. Until then support stays guided: obtain a claim token directly from [Plex](https://www.plex.tv/claim), claim through an approved private setup path, independently verify the signed-in owner, then separately validate an approved library and playback. No Docker run, account action, token handling, library scan, or live acceptance was performed in this review.
