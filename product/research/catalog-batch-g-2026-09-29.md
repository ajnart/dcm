# Catalog batch G: first-run feasibility (2026-09-29)

A pinned, loopback-only `stirling-pdf` recipe and read-only first-run adapter were added after the shared v2 contract gained `no-account`. [Official Docker installation](https://docs.stirlingpdf.com/Installation/Docker%20Install/) says login is **enabled by default** with `admin/stirling`, so this recipe explicitly sets `SECURITY_ENABLELOGIN=false`; [official security configuration](https://docs.stirlingpdf.com/Configuration/Security/System%20and%20Security/) documents that opt-out. The [upstream container registry](https://github.com/Stirling-Tools/Stirling-PDF/pkgs/container/stirling-pdf/versions) lists the pinned `3.0.0` tag. The adapter checks only the local application page on the exact saved loopback origin. PDF processing and restart persistence remain separate acceptance checks. A Compose candidate that starts with known/default credentials, or cannot finish its account initialization through a source-backed call, would not meet the requested deterministic headless first-run boundary.

| App | Source-backed constraint / next work |
| --- | --- |
| seafile | [Seafile 13 Docker instructions](https://manual.seafile.com/13.0/setup/setup_ce_by_docker/) require `INIT_SEAFILE_ADMIN_EMAIL` and `INIT_SEAFILE_ADMIN_PASSWORD` alongside the official multi-service environment. Current private-file recipe onboarding has no supported mapping for this inline password variable. Needs a secure file or bounded API initialization contract and topology review. |
| slskd | [Official configuration](https://github.com/slskd/slskd/blob/master/docs/config.md) documents `SLSKD_PASSWORD` as an inline environment variable and the default `slskd/slskd` Web UI login; Soulseek network credentials are also required to connect. The [official Docker example](https://github.com/slskd/slskd#with-docker) starts with those defaults. Do not ship that as completed first-run. |
| technitium-dns | The [official Compose example](https://github.com/TechnitiumSoftware/DnsServer/blob/master/docker-compose.yml) documents `DNS_SERVER_ADMIN_PASSWORD_FILE`, but no username environment variable matching v2 `initial-admin-from-file`'s required `usernameEnvironment`. DNS service port 53 also requires an explicit interface/port ownership decision; publishing the Web UI alone is not a DNS deployment. |
| tailscale | [Tailscale auth-key guidance](https://tailscale.com/docs/features/access-control/auth-keys/how-to/secure-auth-keys) requires a privately supplied auth key for headless enrollment. It is an external credential and tailnet device authorization, not a generated initial-admin password. A separately approved secret-input and verification contract is needed. |
| tracearr | The [official supervised Compose example](https://github.com/connorgallopo/Tracearr/blob/main/docker/examples/docker-compose.supervised-example.yml) needs at least 3 GiB memory and uses four persistent volumes; its published image tag is moving (`supervised`). The v2 recipe lacks a memory-limit field and the app still needs a verified server-link onboarding path. |

The remaining assigned IDs—`speedtest-tracker`, `stalwart-mail`, `syncthing`, and `tdarr`—were not sufficiently verified for a source-backed pinned recipe plus deterministic first-run adapter in this pass. No deployment or full application acceptance is claimed for any ID.
