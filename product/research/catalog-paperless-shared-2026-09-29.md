# Paperless-ngx shared first run (v3.2.1)

The shared adapter verifies the generated `admin` password against the private `/api/users/` endpoint and requires exactly one active superuser. The existing standalone implementation established this same account check and a successful isolated-instance trial; that proof does not cover the new shared transport. See [v3.2.1 `UserViewSet`](https://github.com/paperless-ngx/paperless-ngx/blob/v3.2.1/src/paperless/views.py#L110-L121) and [the recorded isolated trial](../control-panel-proof.md).

The [pinned URL table](https://github.com/paperless-ngx/paperless-ngx/blob/v3.2.1/src/paperless/urls.py#L213-L223) exposes `/api/ui_settings/` and `/api/token/`; the [token view](https://github.com/paperless-ngx/paperless-ngx/blob/v3.2.1/src/paperless/views.py#L51-L54) uses `PaperlessAuthTokenSerializer`. The adapter submits the saved admin credentials privately once, verifies that the returned token resolves to the same admin ID through UI settings, verifies `/api/statistics/`, then saves the token through the shared owner-only secret interface. Existing tokens are always reverified and are never rotated. A pre-send checkpoint records the token request; an ambiguous lost response without a saved token stops for private inspection rather than blindly repeating the POST.

The existing standalone owner retains its `app login-check`, `paperless-token-plan`, approved `paperless-token-create`, and `paperless-token-status` sequence. Only an exact shared-owner status selects the new private HTTP route. This ports only generated-admin and API-token first run. It does not claim OCR, original-byte retrieval, restart persistence, native Homarr integration, or a live shared-owner trial. The recipe and manifest remain unchanged because their pinned Compose and support claims are independent of this first-run adapter.
