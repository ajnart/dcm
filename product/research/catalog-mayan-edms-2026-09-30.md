# Mayan EDMS shared Compose reassessment — 2026-09-30

Decision: retain discovery support; do not add `recipe.json` or `setup.ts`. This is a source review, not a deployment or login verification.

The [official 4.12.2 Compose installation](https://docs.mayan-edms.com/chapters/docker/install_docker_compose.html) downloads both the upstream Compose file and `.env`. The [current upstream Compose source](https://gitlab.com/mayan-edms/mayan-edms/-/raw/master/docker/docker-compose.yml) has application and background-worker processes plus PostgreSQL, RabbitMQ, Redis, and optional Elasticsearch/Traefik profiles. Its application environment constructs a RabbitMQ broker URL, PostgreSQL database setting, and three distinct Redis result/lock/event URLs using service passwords. RabbitMQ and Redis separately consume those passwords. Replacing the source's published default passwords with generated values is required for a private managed setup.

The shared v2 recipe can bind one generated file to one environment variable and compose a typed PostgreSQL URL. It cannot derive the RabbitMQ URL or the three Redis URLs from generated password files. Literal values in catalog JSON or checked-in configuration would leak credentials; copied upstream defaults would not be a safe managed recipe. This is the first blocker, independent of the larger topology's service-health and profile semantics. Do not publish a reduced one-container candidate as though it were the official deployment.

The [first-steps guide](https://docs.mayan-edms.com/chapters/getting_started.html) documents initial `admin` credentials generated on first start, and optional `MAYAN_AUTOADMIN_USERNAME`/`MAYAN_AUTOADMIN_PASSWORD` environment variables set before first start. These are bootstrap inputs, not a documented rotation mechanism for an existing database. An adapter would need to bind a generated password through the owner-only secret environment and prove, on first run and replay, that the saved account authenticates. The [4.12.2 release notes](https://docs.mayan-edms.com/chapters/releases/4.12.2.html) state that the REST current-user endpoint requires authentication, but the reviewed installation and first-steps material do not establish a pinned username/password-to-token or login-check contract. An HTTP 200 at `/`, process health, or the first-run sign-in page does not prove admin ownership.

Unblock in order: add typed, secret-safe derivation for the broker and Redis connection settings; model the official pinned topology and durable volumes without weakening its startup dependencies; establish an official-version authenticated current-user contract; then verify a fresh bootstrap, idempotent replay, document round-trip, restart persistence, and isolated restore. No Docker, browser, or live Mayan instance was used in this assessment.
