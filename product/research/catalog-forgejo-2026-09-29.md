# Forgejo 16.0.5 catalog boundary

Checked 2026-09-29 against Forgejo's versioned primary documentation.

- The [download page](https://forgejo.org/download/) publishes `codeberg.org/forgejo/forgejo:16.0.5`. The [v16 Docker guide](https://forgejo.org/docs/v16.0/admin/installation/docker/) documents a one-service Compose deployment, `/data` persistence, HTTP port 3000, and optional container SSH port 22. It says SQLite is the default without an external database. The recipe uses the fixed patch tag and a project-owned volume, and keeps HTTP on loopback by default; SSH remains an explicit optional private port selection.
- The [v16 command-line guide](https://forgejo.org/docs/v16.0/admin/command-line/) documents `forgejo admin user create` with username, password, email, and `--admin`, plus `forgejo admin user generate-access-token` with username, token name, scopes, and `--raw`. These are in-container administrative operations, not documented first-run HTTP endpoints.
- The shared setup contract now offers exact-owner container execution with stdin and a pre-send checkpoint. That does not change Forgejo's CLI contract: `admin user create` documents `--password`, but no password-from-file or stdin option. A shell that reads the generated password from stdin and passes `--password "$password"` exposes it in the **container process argv**. `--random-password` would create a credential different from the saved handoff file and may print it in command output. An uncertain create outcome also needs ownership-aware replay and login verification. **No adapter is added.** Shared setup must report Forgejo onboarding pending; the recipe and Compose start are not account acceptance.
- Before a headless adapter can be added, verify an upstream-supported file/stdin password path or a bounded HTTP bootstrap flow, then implement replay-safe account inspection and saved-password verification. A token also needs one-time private capture and replay safety. Neither path is established here.
- The recipe does not configure public ingress, external SSH access, Actions runners, package registry, or backups. Those require separate choices and acceptance. A successful HTTP response alone proves none of the administrator, Git, or persistence checks.
