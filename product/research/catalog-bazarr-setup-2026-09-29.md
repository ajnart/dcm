# Bazarr v1.6.0 headless Basic first-run — 2026-09-29

The [pinned configuration](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/config.py#L175-L180) generates a 32-hex `auth.apikey`, with no initial auth type or user. The [pinned UI route](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/ui.py#L47-L108) injects that key into the initial page before auth is enabled and requires valid HTTP Basic credentials after `auth.type=basic`. The [HTML template](https://github.com/morpheus65535/bazarr/blob/v1.6.0/frontend/index.html) serializes that injection in `window.Bazarr = JSON.parse(...)`.

The [settings route](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/api/system/settings.py#L19-L39) requires the generated key for GET and form POST; the [authentication decorator](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/api/utils.py#L17-L29) accepts `X-API-KEY`. The [settings saver](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/config.py#L639-L685) stores a changed password as MD5. The adapter therefore reads only the exact private UI, validates the 32-hex key, verifies pristine auth settings, saves the key privately, checkpoints before one Basic-auth settings POST, then reads back auth settings and proves both successful Basic GET `/` and denied anonymous GET `/`. On replay it uses the saved key and checkpoint for read-only verification, never blind re-POST.

This intentionally uses Basic, not Forms, to give a verifiable headless credential route. It does not configure Sonarr, Radarr, subtitle providers, `/data` mappings, or restart persistence. No Docker or live-instance acceptance was performed; the source-level adapter still needs a fresh-image check before claiming deployed success.
