# AdGuard Home shared Compose candidate — 2026-09-29

AdGuard Home v0.107.79 is the latest stable release observed on the [official releases page](https://github.com/AdguardTeam/AdGuardHome/releases/tag/v0.107.79). The matching [official image tag](https://hub.docker.com/r/adguard/adguardhome/tags?name=v0.107.79) is `adguard/adguardhome:v0.107.79`. The [Docker guide](https://github.com/AdguardTeam/AdGuardHome/wiki/Docker) documents persistent `/opt/adguardhome/work` and `/opt/adguardhome/conf` paths, port 3000 for initial administration, and separate DNS port 53 TCP/UDP. It warns about host resolver conflicts.

The [versioned OpenAPI specification](https://raw.githubusercontent.com/AdguardTeam/AdGuardHome/v0.107.79/openapi/openapi.yaml) documents `GET /control/install/get_addresses`, `POST /control/install/configure`, and Basic-authenticated `GET /control/status`. Initial configuration takes `dns` and `web` address/port objects plus `username` and `password`; status returns `version`, `http_port`, `dns_port`, and `running`. The adapter binds web to port 3000 and DNS to port 53 inside the container, marks the one-time configure request attempted before sending, and verifies the saved admin credential against status. A lost response is not retried automatically.

The recipe publishes only TCP 3000 to loopback. It does **not** publish DNS port 53, alter `systemd-resolved`, DHCP/router settings, or client DNS. It is an administration-only candidate, not usable LAN filtering. DNS cutover needs separate owner approval, exact TCP/UDP 53 binding and collision review, client resolution/filtering proof, and fallback DNS. No live Docker deployment, DNS query, restart-persistence check, or fresh-profile acceptance was performed.
