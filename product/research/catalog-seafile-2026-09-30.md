# Seafile CE 14.0 catalog research

Research date: 2026-09-30. Scope: official Seafile sources only; no runtime verification.

Recheck decision: retain guided support and do not add a v2 shared recipe or setup adapter. The official CE 14.0 setup page remained available in this recheck and still describes a public hostname, first-start admin environment values, and the stock Caddy topology; the exact Compose YAML URL did not return a fresh page through the web fetch. The unresolved nondefault private host-port URL contract below is therefore still a deployment blocker, not a reason to guess a hostname or mark login-ready.

## Deployment contract

- The official CE 14.0 flow downloads `.env`, `seafile-server.yml`, `seadoc.yml`, and `caddy.yml`, then runs `docker compose up -d`. The template selects `seafileltd/seafile-mc:14.0-latest`, MariaDB 10.11, Redis, Caddy, and SeaDoc by default. [CE Docker setup](https://manual.seafile.com/14.0/setup/setup_ce_by_docker/) · [CE Compose](https://manual.seafile.com/14.0/repo/docker/ce/seafile-server.yml) · [CE environment](https://manual.seafile.com/14.0/repo/docker/ce/env)
- Persistent defaults are `/opt/seafile-data`, `/opt/seafile-mysql/db`, `/opt/seafile-caddy`, and `/opt/seadoc-data`; the manual discourages changing the main data paths unless the operator accounts for the change. The minimum documented CE host is 2 CPU cores, 2 GiB RAM, and 10 GiB free disk (50 GiB recommended). [CE Docker setup](https://manual.seafile.com/14.0/setup/setup_ce_by_docker/) · [system requirements](https://manual.seafile.com/14.0/setup/system_requirements/)
- Required first-deployment values are `SEAFILE_SERVER_HOSTNAME`, a `JWT_PRIVATE_KEY` of at least 32 characters, `SEAFILE_MYSQL_DB_PASSWORD`, `INIT_SEAFILE_MYSQL_ROOT_PASSWORD`, `INIT_SEAFILE_ADMIN_EMAIL`, and `INIT_SEAFILE_ADMIN_PASSWORD`. The three `INIT_*` values are explicitly first-start inputs; the admin values create the initial administrator. [CE Docker setup](https://manual.seafile.com/14.0/setup/setup_ce_by_docker/) · [CE environment](https://manual.seafile.com/14.0/repo/docker/ce/env)
- The checked official Compose defaults are not private/nondefault-port safe: Caddy publishes host ports `80:80` and `443:443`, mounts `/var/run/docker.sock`, while the Seafile service itself has no active published port (only a commented `80:80` example). Database and Redis have no host-published ports. [Caddy Compose](https://manual.seafile.com/14.0/repo/docker/caddy.yml) · [CE Compose](https://manual.seafile.com/14.0/repo/docker/ce/seafile-server.yml)

## Private nondefault host port

- Seafile's current reverse-proxy guidance says to remove `caddy.yml` from `COMPOSE_FILE`, publish Seafile container port 80, remove its Caddy labels, and place the chosen reverse proxy in front. It documents Seafile's internal listen port as 80. [other reverse proxy](https://manual.seafile.com/latest/setup/use_other_reverse_proxy/)
- For a private direct host binding, the bounded Compose mapping is therefore `127.0.0.1:<host-port>:80`, with Caddy omitted and labels removed. This exact loopback/nondefault mapping is a Compose-level inference from Seafile's documented internal port, not a Seafile 14.0 recipe. Keep `SEAFILE_SERVER_PROTOCOL` and `SEAFILE_SERVER_HOSTNAME` aligned with the URL clients actually use; the official 14.0 docs describe the hostname value as a public hostname/domain and do not explicitly confirm `host:port` syntax.
- If SeaDoc remains enabled, exposing only Seafile port 80 is incomplete: the official reverse-proxy table assigns SeaDoc its own upstream and requires WebSocket proxying for `/sdoc-server/` and `/socket.io`. For a minimal single-port private catalog entry, disable SeaDoc (`ENABLE_SEADOC=false`) unless the catalog also owns those proxy routes. [other reverse proxy](https://manual.seafile.com/latest/setup/use_other_reverse_proxy/) · [SeaDoc integration](https://manual.seafile.com/14.0/extension/setup_seadoc/)

## Credential and API verification

Do not put credentials or the returned token in commands, logs, evidence, or catalog preferences. At the narrow verification boundary:

1. POST JSON `{ "username": "<admin-email>", "password": "<admin-password>" }` to `<base-url>/api2/auth-token/`. A successful response is HTTP 200 with a JSON `token` string (the current reference specifies 40 characters). If 2FA is enabled, also send `X-SEAFILE-OTP`. [obtain account token](https://seafile-api.readme.io/reference/post_api2-auth-token)
2. GET `<base-url>/api2/account/info/` with `Authorization: Bearer <token>`. For Seafile versions before 11, the scheme was `Token`; CE 14 uses `Bearer`. Require HTTP 200 and validate that the returned `email` or `login_id` identifies the expected account and that `is_staff` is `true` for the initialized administrator. This proves authenticated account identity/admin status, not application-wide health or file transfer behavior. [authentication](https://seafile-api.readme.io/reference/authentication) · [account info](https://seafile-api.readme.io/reference/get_api2-account-info)
3. Optionally, an unauthenticated GET to `<base-url>/api2/server-info/` can record server version information, but it does not prove login or administrator privileges. [server information](https://seafile-api.readme.io/reference/get_api2-server-info)

## Exact blockers / uncertainty

- No official CE 14.0 page found documents a loopback-only nondefault host-port deployment end to end. The official stock topology publicly binds 80/443 through Caddy; the documented alternative-proxy topology assumes a separately managed proxy. A catalog claiming `127.0.0.1:<port>` support must own and validate that Compose override plus generated Seafile URLs.
- The official API reference embedded OpenAPI currently reports version 13.0 even though the 14.0 manual links to it. Endpoints, Bearer authentication, and response fields are official current documentation, but they were not runtime-verified against CE 14.0 in this research.
- Seafile's [12.0 upgrade notes](https://manual.seafile.com/14.0/upgrade/upgrade_notes_for_12.0.x/) say `SERVICE_URL` is calculated from `SEAFILE_SERVER_PROTOCOL` and `SEAFILE_SERVER_HOSTNAME`. This makes the external authority a functional concern, not merely a UI link. The current 14.0 setup guide still describes the hostname input only as a public hostname or domain. Neither source establishes how a selected nondefault loopback port should be encoded, so a shared Compose recipe and headless adapter remain unpublished pending a sourced mapping and fresh-instance file-link check.
- Initial-admin environment variables apply only on first startup. They are not a supported way to rotate/reset an existing administrator; the CE manual instead documents `reset-admin.sh` inside the running container.
- HTTP 200 from the UI, token issuance, and account-info are narrow observations. They do not establish upload/download correctness, SeaDoc/WebSocket behavior, persistence, backup/restore, upgrade safety, or external acceptance.
