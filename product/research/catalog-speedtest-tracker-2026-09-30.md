# Speedtest Tracker first-run boundary — 2026-09-30

The pinned catalog image is `lscr.io/linuxserver/speedtest-tracker:v1.14.7-ls165`. The existing recipe supplies a generated 48-byte alphanumeric `ADMIN_PASSWORD`, a fixed `ADMIN_EMAIL=admin@example.test`, a generated `APP_KEY`, and a loopback-only published UI. [Upstream's environment reference](https://docs.speedtest-tracker.dev/getting-started/environment-variables) says the administrator email and password affect only initial setup. This prevents the documented public default on a *fresh* database, but does not rotate or verify an administrator in an existing volume.

[Upstream's authentication guide](https://docs.speedtest-tracker.dev/security/authentication) documents the public default `admin@example.com` / `password` and UI profile/account edits. [Its authorization table](https://docs.speedtest-tracker.dev/security/authorization) reserves user management and API-token management for admins; a successful login alone would not prove that role. [Its API authorization guide](https://docs.speedtest-tracker.dev/api/authorization) points administrators to `/admin/api-tokens` for token creation. None establishes a stable, pinned-version HTTP login, role readback, credential-rotation, or token-creation contract for an unattended adapter. The published [OpenAPI](https://github.com/alexjustesen/speedtest-tracker/blob/1.x/openapi.json) describes bearer-token use, not authenticated bootstrap or token creation. The [LinuxServer release](https://github.com/linuxserver/docker-speedtest-tracker/releases/tag/v1.14.7-ls165) links its remote changes to upstream v1.14.7, but the image tag identifies packaging, not an independently proven application source revision; no image digest or source-to-image mapping was established here.

Decision: leave `setup.ts` absent and shared setup pending. An adapter that treats HTTP 200 or a reachable `/admin` login page as credential readback would falsely mark a reused volume configured. Guessing Filament/Livewire request shapes, reading SQLite directly, or submitting the documented default on an ambiguous volume would risk mis-owning or exposing an account. A safe direct-HTTP adapter needs a pinned login request contract, authenticated admin-role readback, and explicit retry behavior for an existing volume; those are not documented. The generated credential can be handed off privately for operator login, but must not be reported as verified until a fresh login and administrator role are observed. Token creation, measurement, and restart persistence remain separate manual acceptance checks. No Docker run or live acceptance was performed.

Pinned-source follow-up: upstream tag [`v1.14.7`](https://github.com/alexjustesen/speedtest-tracker/tree/v1.14.7) resolves to commit `05621935b64192bf2e86fa1ac2e6db6f40857e2c`. Its [admin panel provider](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/app/Providers/Filament/AdminPanelProvider.php) configures Filament's `admin` path and `login()` rather than an application-defined HTTP login action. The [user model](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/app/Models/User.php) permits every user to access that panel; therefore a successful panel login or `/admin` response does not prove an admin role. The [user policy](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/app/Policies/UserPolicy.php) gates user listing on `is_admin`, and the [initial migration](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/database/migrations/2014_10_12_000000_create_users_table.php) seeds the configured account with the `admin` role only when the users table is created. The pinned `composer.lock` selects Filament `v5.7.3` and Livewire `v4.3.3`. The app's [web routes](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/routes/web.php) redirect `/login` to the Filament login, while its [API routes](https://github.com/alexjustesen/speedtest-tracker/blob/v1.14.7/routes/api.php) provide no session login or current-user role readback. An HTTP adapter would have to reproduce framework-owned Livewire login traffic and infer role from a protected UI page; that is not a stable, app-owned contract and was not proven against the pinned LinuxServer image. Keep the pending/manual boundary.
