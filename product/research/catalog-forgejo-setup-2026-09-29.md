# Forgejo shared setup boundary — 2026-09-29

Decision: leave the v16.0.5 Forgejo recipe inspectable without a shared `setup.ts` adapter. The existing `manual-first-admin` recipe prepares a private admin-password file, but the pinned upstream CLI does not accept that password over stdin or from a file.

The [v16.0 command-line reference](https://forgejo.org/docs/v16.0/admin/command-line/) documents `forgejo admin user create --username ... --password ... --email ... --admin`. It also offers `--random-password`, but does not document a password-stdin or password-file option for this command. Passing the generated password through `--password`, including via an in-container shell expansion, would expose it in the command's argv and violate the shared `SetupContainerCommand` contract. A random CLI password would not match the recipe's saved credential and cannot be recovered for `app handoff`. The command also requires an email identity; the current recipe does not collect one.

Forgejo's [Docker installation guide](https://forgejo.org/docs/v16.0/admin/installation/docker/) directs a fresh installation to browser onboarding. It does not establish a headless first-admin HTTP contract for this pinned deployment. The [API usage guide](https://forgejo.org/docs/v16.0/user/api/usage/) documents authenticated API use, not a way to bootstrap the first administrator before installation. Token creation must follow verified administrator ownership; the [CLI reference](https://forgejo.org/docs/v16.0/admin/command-line/) lists `admin user generate-access-token`, but creating a token is not a substitute for safely creating and authenticating the first account. Do not label the admin password an API token or report a token that was not created and saved.

A future adapter needs a version-pinned upstream-supported secret-safe first-admin input, or a separately reviewed first-run web flow with exact route/CSRF/session behavior, non-secret email choice, before-send checkpointing, and authenticated administrator read-back. Token creation, if requested, needs its own scoped approval, one-time-secret capture, and authenticated verification. Compose start and an HTTP response are not account or Git round-trip acceptance. No live container, browser onboarding, restart, or Git round-trip was exercised here.

## Recheck — 2026-09-30

The pinned [v16.0 CLI reference](https://forgejo.org/docs/v16.0/admin/command-line/) still lists only `--password` (an argv value) or `--random-password` for `admin user create`; it also requires `--email`. Neither option safely consumes the recipe's generated password through the shared container-command stdin. The [v16.0 API guide](https://forgejo.org/docs/v16.0/user/api/usage/) documents BasicAuth and one-time token generation for an existing account, not first-admin bootstrap. No `setup.ts` was added and the recipe remains guided/pending. A deterministic shared adapter needs a source-proven first-admin route that accepts the saved secret outside argv, plus a reviewed non-secret email identity and authenticated read-back. This is a source-contract recheck, not live acceptance.
