# Passbolt CE catalog: shared recipe decision (2026-09-30)

Status: discovery-only; no v2 shared Compose recipe or `setup.ts` adapter.

Official [Docker installation guide](https://www.passbolt.com/docs/hosting/install/ce/docker/) names a working SMTP server and NTP as prerequisites. Its example defaults to `https://passbolt.local` with a self-signed certificate and a floating image tag, both requiring deliberate replacement for a real deployment. The documented first-admin action is `passbolt register_user` run as `www-data`; it outputs a one-time browser registration URL. It does **not** set or return an administrator password. The owner must finish registration in a trusted browser at the final HTTPS origin, create and protect their key/recovery kit, then demonstrate a fresh authenticated sign-in.

The [environment reference](https://www.passbolt.com/docs/hosting/configure/environment-reference/) requires `APP_FULL_BASE_URL` to reflect the actual origin, describes SMTP settings, and marks `PASSBOLT_SSL_FORCE=false` as unsafe for production. The [Docker TLS guide](https://www.passbolt.com/docs/hosting/tls/ce/docker-manual/) calls for certificate/key mounts and an HTTPS base URL. Its warning says a later HTTP-to-HTTPS domain change unlinks users' browser extensions; the [FQDN guide](https://www.passbolt.com/docs/hosting/fqdn/) likewise treats origin changes as an account-recovery operation.

The current shared v2 recipe contract only derives `local-origin` from the loopback-published port. It has no reviewed private HTTPS origin, certificate/trust handoff, external SMTP configuration, or onboarding kind for `register_user` followed by owner-controlled browser key creation. `manual-first-email` would incorrectly promise a generated saved admin password. A recipe or adapter built from these fields could start containers but cannot establish a usable vault. Keep Passbolt discovery-only until the shared contract can represent and verify the full path. Do not elevate HTTP 200, container health, or issuance of a registration link to acceptance.

Required future gate: confirm private DNS/origin and trusted TLS before apply; configure and prove outbound SMTP and time; pin official image versions and persist DB/GPG/JWT material; issue one-time first-admin registration only after explicit approval; complete owner registration; verify fresh login, encrypted secret round-trip, recovery-kit custody, restart persistence, and an isolated restore. No live deployment or browser acceptance was attempted for this research.
