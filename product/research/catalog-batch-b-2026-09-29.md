# Catalog batch B: headless setup feasibility (2026-09-29)

No batch-B recipe or adapter was added. The current v2 recipe requires an `onboarding` variant, but its variants are limited to manual admin, a file-seeded admin, Jellyfin-dependent admin, and the Immich-specific API. The `SetupContext` can use an exact saved loopback HTTP origin and narrowly defined actions; it cannot execute an app's admin CLI, inject an operator-provided external token as a secret, or create an arbitrary configuration file. Adding a recipe without an honest first-run path would present an incomplete candidate as runnable.

## Second pass after `no-account` support

The new `no-account` variant removes Dashdot's schema obstacle, but not its deployment obstacle. The upstream [Compose example](https://getdashdot.com/docs/installation/docker-compose) requires `privileged: true` and a read-only mount of host `/` at `/mnt/host`. The current recipe schema has no privileged declaration, and the repo prohibits broad host mounts by default. Replacing these with narrow mounts would change the metrics contract without upstream evidence. Its documented [`/info` and `/config` endpoints](https://getdashdot.com/docs/integration/api) could support a read-only setup adapter **after** a separately reviewed host-access design; HTTP readback alone cannot make this deployment safe.

The nearest code-ready draft is Forgejo's official [v16 Docker recipe](https://forgejo.org/docs/v16.0/admin/installation/docker/): `codeberg.org/forgejo/forgejo:16.0.5` from the [official download page](https://forgejo.org/download/), SQLite by default, persistent `/data`, private loopback port 3000, and optional SSH port 22 only after an explicit mapping choice. Its first admin should be created by the documented [`forgejo admin user create`](https://forgejo.org/docs/v15.0/admin/command-line/) command with `--username`, `--password`, `--email`, and `--admin`; the password must never appear in a host command argument, checkpoint, or output. The exact missing primitive is an app-owned, approved container-exec operation with a private stdin or file-backed password transport, exact-container ownership check, pre-send checkpoint, and post-create readback. `SetupContext.apply` currently accepts only registered actions and has no such Forgejo action. A `manual-first-admin` recipe would be a usable guided Compose candidate, but would not satisfy the requested deterministic headless first run, so no draft recipe was added.

The next implementation boundary is a reviewed contract for privileged host visibility or app-owned CLI admin creation, followed by version-pinned HTTP/CLI verification. None of those shared-contract changes were in this batch's file scope.
