# Mayan EDMS shared Compose assessment — 2026-09-29

Decision: keep Mayan EDMS at discovery. Do not add a recipe or `setup.ts` yet. No Docker instance was started or validated.

The current [official Compose installation](https://docs.mayan-edms.com/chapters/docker/install_docker_compose.html) uses the upstream `docker/docker-compose.yml` together with its `.env`, not a documented one-container deployment. The [upstream Compose source](https://gitlab.com/mayan-edms/mayan-edms/blob/master/docker/docker-compose.yml) combines Mayan app/worker processes with PostgreSQL, RabbitMQ, and Redis, including credential-bearing broker, result-backend, lock-manager, event-stream, and database connection settings. It also has service health dependencies and persistent volumes. A reduced topology or copied default passwords would be an unverified deployment contract.

The [current first-steps guide](https://docs.mayan-edms.com/chapters/getting_started.html) says first start creates an `admin` account with a random password shown on the sign-in page. It documents `MAYAN_AUTOADMIN_USERNAME` and `MAYAN_AUTOADMIN_PASSWORD` environment variables to choose initial credentials before first start. It does not document a corresponding password-file variable. These are empty-database bootstrap settings, not evidence that changing them later rotates an existing administrator. A safe shared handoff would need an owner-only secret environment binding, then verify login and identity after startup; container liveness and HTTP 200 are insufficient.

The present v2 recipe primitives cannot safely express the official topology's several connection strings containing the same generated broker/Redis/database secrets. `secretEnvironment` binds one generated file to a single environment variable, and the typed URL composer covers only a PostgreSQL URL. It cannot derive the RabbitMQ URL and distinct Redis result, lock, and event URLs without putting credentials in catalog JSON or inventing unsupported interpolation. This is the first blocking boundary for a recipe. The pinned image/tag and per-service initialization behavior must also be established from the same official release before representing it as a candidate.

For setup, the [4.12.2 release notes](https://docs.mayan-edms.com/chapters/releases/4.12.2.html) confirm that the REST API current-user endpoint requires authentication, but do not establish a pinned username/password token-acquisition or login contract suitable for independent admin verification. Do not use an unauthenticated page scrape of the displayed random password, log scraping, or a guessed API route. After the Compose/secret boundary is implemented, verify a documented authenticated current-user flow and a harmless document upload/readback, restart persistence, and isolated restore before claiming acceptance.
