# Authentik Compose and bootstrap boundary (2026-09-29)

Decision: keep Authentik guided without a shared recipe or `setup.ts` for now. The current shared recipe compiler cannot safely produce the first-start Django password hash required by the recommended bootstrap path. A plain password environment variable is documented but explicitly discouraged by Authentik. A login page alone is not IdP acceptance.

## Upstream contract

- The [official Compose installation](https://docs.goauthentik.io/install-config/install/docker-compose/) is for small/test deployments, requires at least 2 cores and 2 GiB RAM, generates a PostgreSQL password and `AUTHENTIK_SECRET_KEY`, and publishes HTTP 9000/HTTPS 9443 by default. A future recipe should bind privately and pin an exact release/image digest rather than follow the moving downloaded Compose file. Do not add `/etc/timezone` or `/etc/localtime` mounts; Authentik warns they disrupt OAuth/SAML.
- The [current architecture](https://docs.goauthentik.io/core/architecture/) requires server, worker, and PostgreSQL. [Release 2025.10](https://docs.goauthentik.io/releases/2025.10) removed Redis entirely; the catalog's stale Valkey dependency was removed.
- Official Compose mounts `/var/run/docker.sock` in the worker for automatic outpost management, but [the installation guide](https://docs.goauthentik.io/install-config/install/docker-compose/) explicitly allows removing it and manually managing outposts. No socket mount should enter this repository's bounded Compose project; automatic outpost management remains outside acceptance.
- [Automated install](https://docs.goauthentik.io/install-config/automated-install/) supports worker-only, first-start `AUTHENTIK_BOOTSTRAP_PASSWORD_HASH` for `akadmin`, `AUTHENTIK_BOOTSTRAP_TOKEN`, and optional email. The hash must be generated by Authentik's `server hash_password` command from a private password via stdin/file; these bootstrap values cannot use Authentik's `file://` secret syntax. `AUTHENTIK_BOOTSTRAP_PASSWORD` stores plaintext in the container environment and is explicitly discouraged. Both password forms are first-start only, not rotation mechanisms.
- An API token can verify a private `GET /api/v3/core/users/me/` with `Authorization: Bearer` per the [official API reference](https://docs.goauthentik.io/docs/developer-docs/api/reference/core-users-me-retrieve). This proves token identity, not interactive login, break-glass usability, SSO provider behavior, or recovery.

## Missing recipe/setup primitive

The shared recipe can generate private files and bind them to environment variables, but cannot run the pinned server's `hash_password` command before Compose startup, capture its salted output privately, and inject the resulting hash into only the worker's first-start environment. The existing `SetupContext.container.exec` is a post-start adapter boundary and therefore too late for that bootstrap. Changing the shared engine/schema is outside this app task. Until that pre-start credential derivation has an owner and separate approval, do not add a recipe that falls back to discouraged plaintext bootstrap. A later adapter must verify the bootstrap token against the exact `akadmin` identity, independently verify interactive password login and break-glass access, and handle existing-database replay without assuming first-start variables rotated credentials.

This was official-documentation review only. No Docker action, live Authentik request, or tests were run.
