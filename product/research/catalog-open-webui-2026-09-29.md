# Open WebUI catalog decision — 2026-09-29

The official Docker quick start uses `ghcr.io/open-webui/open-webui`, port 8080, a persistent `/app/backend/data` volume, and a stable `WEBUI_SECRET_KEY`. The v0.11.4 release provides a fixed image tag. The recipe keeps the host bind on loopback and does not implicitly attach Ollama or any cloud provider.

The [environment reference](https://docs.openwebui.com/reference/env-configuration/) and [roles guide](https://docs.openwebui.com/features/authentication-access/rbac/roles/) document `WEBUI_ADMIN_EMAIL` plus `WEBUI_ADMIN_PASSWORD` as a first-start, empty-database admin bootstrap that disables signup. The new `secretEnvironment` binding could supply the generated password and stable secret key from private files. This is a container-environment secret, not a Docker secret-file interface; operators with container-inspection access can still see it. An existing volume is not reset by these variables.

The recipe uses the new `initial-admin-email-from-secret-env` contract with fixed `admin@example.test`, generated `WEBUI_ADMIN_PASSWORD`, and persistent generated `WEBUI_SECRET_KEY`. It mounts `/app/backend/data`, binds host port 8080 only on loopback, and does not attach a model server. The email is a local login identity, not an approved or verified mailbox. The setup adapter submits the saved password to the exact private sign-in route and checks the returned email and admin role; it discards the bearer token.

The [API-key guide](https://docs.openwebui.com/features/authentication-access/api-keys/) documents a global enablement gate and account-UI creation; a second creation invalidates the existing key. This is unsafe to automate without a version-pinned, read-before-write API contract and a lost-response recovery policy. No live admin login, API key, provider connection, chat, or restart persistence has been observed. The [quick start](https://docs.openwebui.com/getting-started/quick-start/) and [v0.11.4 release](https://github.com/open-webui/open-webui/releases/tag/v0.11.4) establish deployment facts, not live acceptance.

The [v0.11.4 `auths.py`](https://github.com/open-webui/open-webui/blob/v0.11.4/backend/open_webui/routers/auths.py) defines `POST /signin` (email/password) and returns a bearer session token. The app mounts it at `/api/v1/auths`; the adapter calls only that exact route. API-key mutation routes still need an explicit safety review. The sign-in token must never enter a report or checkpoint.
