# Cloudflare Tunnel catalog boundary — 2026-09-30

Cloudflare's official image has the versioned `cloudflare/cloudflared:2026.9.1` tag. Its documented Docker command runs `tunnel --no-autoupdate run --token <TUNNEL_TOKEN>`. For a remotely managed tunnel, Cloudflare also documents `TUNNEL_TOKEN` and, since cloudflared 2025.4.0, `TUNNEL_TOKEN_FILE` for a file containing that token. The token is issued by Cloudflare for a specific tunnel; it is not an application-generated random password. Anyone holding it can run a connector for that tunnel.

**No bundled recipe or setup adapter yet.** The v2 recipe contract's `privateFiles` generates random bytes and its `secretEnvironment` only binds those generated bytes. It cannot accept an existing provider-issued secret as a private, owner-scoped input or mount it as a token file. Modeling the token as a generated private file, literal environment value, non-secret setup input, or command argument would be incorrect or leak it. The setup adapter has no typed API to obtain this external token either. Thus the manifest remains `guided`, and there is no honest `recipe.json`/`setup.ts` in this folder.

The minimum shared-contract addition is an externally supplied secret-file reference, bound to a fixed `TUNNEL_TOKEN_FILE` path for the exact Compose owner, plus private input/handoff and resume semantics. Its value must stay out of command arguments, catalog JSON, plans, ordinary logs, and reports. A later recipe could use the pinned image with `tunnel --no-autoupdate run`, no host-published ports, and a private metrics/readiness endpoint only if upstream behavior is confirmed. A setup adapter must verify connector identity and health against the exact selected tunnel, not infer acceptance from container liveness.

No public hostname, DNS entry, origin mapping, Access policy, or private-network route is included. Cloudflare documents that adding a published-application route can make an origin Internet-accessible; each route needs separate authorization and an explicit DNS/TLS/auth owner. A connected tunnel alone proves neither route reachability nor application access control.
