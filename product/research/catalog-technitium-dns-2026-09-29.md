# Technitium DNS shared recipe — 2026-09-29

The [official Compose example](https://github.com/TechnitiumSoftware/DnsServer/blob/master/docker-compose.yml) documents web port 5380, TCP/UDP DNS port 53, `DNS_SERVER_ADMIN_PASSWORD_FILE`, and persistent `/etc/dns` and `/var/log/technitium/dns` volumes. The [publisher's image tags](https://hub.docker.com/r/technitium/dns-server/tags) include `15.5.1`; the [changelog](https://github.com/TechnitiumSoftware/DnsServer/blob/master/CHANGELOG.md) dates it 26 September 2026 and records a session-token security fix. The recipe pins that version, uses the image-default user, generates a private admin-password file, and publishes only the web console on `127.0.0.1:5380`. It intentionally omits DNS port 53: choosing a LAN address, resolver clients, firewall path, and fallback DNS is a separate owner-approved cutover.

The [official API documentation](https://github.com/TechnitiumSoftware/DnsServer/blob/master/APIDOCS.md) specifies form-encoded `POST /api/user/login`, returning an administrator session token, and bearer-authenticated `GET /api/user/profile/get`. The adapter checks the saved generated password through those calls and retains neither password nor session token in a checkpoint. Login is repeatable; it does not create an API token or change server settings. The same docs describe non-expiring API tokens, so automatic creation would need a separate least-privilege user, one-shot credential capture, and replay policy. No DNS query, LAN availability, restart persistence, or live-image behavior was verified here.
