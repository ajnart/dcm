# Nginx Proxy Manager catalog candidate — 2026-09-29

The official [v2.16.0 release](https://github.com/NginxProxyManager/nginx-proxy-manager/releases/tag/v2.16.0) publishes `jc21/nginx-proxy-manager:2.16.0`. The [official setup](https://nginxproxymanager.com/setup/) mounts `/data` and `/etc/letsencrypt` and exposes 80, 81, and 443. This recipe publishes only the admin listener, port 81, on a selected private host binding; it does not claim a functioning public reverse proxy.

The [advanced configuration](https://nginxproxymanager.com/advanced-config/) documents `INITIAL_ADMIN_EMAIL` and `INITIAL_ADMIN_PASSWORD` for first-user creation. The candidate binds a generated 48-character alphanumeric password through the shared engine's owner-only secret env file; its value is absent from catalog data. The email is fixed, lowercase, and non-secret. The image runs as its default user because upstream warns that a numeric user may fail to bind port 80.

The tagged API schema documents [POST /tokens](https://github.com/NginxProxyManager/nginx-proxy-manager/blob/v2.16.0/backend/schema/paths/tokens/post.json) with `identity` and `secret`, then [GET /users/me](https://github.com/NginxProxyManager/nginx-proxy-manager/blob/v2.16.0/backend/schema/paths/users/userID/get.json) with a bearer token. The app-local headless adapter checks that the saved login resolves to an enabled user with the expected email and `admin` role; it discards the token. A two-factor challenge requires manual completion. The schema does not establish a durable API-key setup contract, so the adapter creates or claims no API key.

Before any live apply: verify the pinned image digest, host ownership and port collisions, and fresh-instance bootstrap behavior. Public ports 80/443, DNS, TLS, auth, and proxy-host configuration require separate ingress ownership and approval. A private admin UI alone does not constitute public ingress acceptance. Backup and isolated restore must cover both persistent mounts.
