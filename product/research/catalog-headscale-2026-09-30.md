# Headscale catalog boundary (2026-09-30)

Decision: retain `guided` support. Do not publish a shared v2 recipe or `setup.ts` yet.

The [container guide](https://headscale.net/stable/setup/install/container/) describes a pinned `headscale/headscale:<VERSION>` image, a version-matched `/etc/headscale/config.yaml`, persistent `/var/lib/headscale`, private 8080/9090 publishes, `headscale health`, and `/health`. It explicitly says the container guide is community-maintained and unverified by Headscale developers. The [configuration reference](https://headscale.net/stable/ref/configuration/) requires a YAML file and recommends the example from the same release tag; the [v0.29.4 example](https://raw.githubusercontent.com/juanfont/headscale/v0.29.4/config-example.yaml) has a client-facing `server_url`, default loopback `listen_addr`, separate private metrics and gRPC listeners, SQLite state, and a DNS base domain that must differ from the server URL domain. A literal example config is not a working deployment.

The shared recipe's `configFiles` are fixed, review-bound text. They cannot currently derive `server_url` from the owner's reviewed HTTPS origin or bind a distinct selected MagicDNS domain. A fixed placeholder or loopback `server_url` would produce a misleading deployment even if `/health` passed. The missing capability is typed, approval-bound non-secret config rendering from a selected origin and DNS domain, with exact-content resume checks. Deployment also needs a separately approved DNS/TLS/443 owner and an external health check at that origin. Do not weaken private-default exposure to work around this.

The [API reference](https://headscale.net/stable/ref/api/) documents `headscale apikeys create`, Bearer authentication, and that a key cannot be retrieved after creation. Headscale has no web first-administrator account to invent. A future adapter should verify the selected public HTTPS `/health` route and, only after the config and origin are proven, checkpoint before one-time key creation, save the output in an owner-only credential file, and verify an authenticated API read. A lost create response must halt for operator reconciliation; `apikeys list` cannot recover the secret. Local health alone does not prove registration, DNS, DERP, mesh connectivity, or restart persistence; those require separate acceptance.
