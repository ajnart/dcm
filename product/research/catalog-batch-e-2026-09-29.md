# Catalog batch E: first-run feasibility (2026-09-29)

Scope: netdata, nginx-proxy-manager, node-red, ntfy, nzbget, ollama, open-webui, pangolin, passbolt, patchmon. Ollama now has a private Compose recipe and a read-only headless API setup adapter under the new `no-account` onboarding contract. The remaining apps need a documented contract or user decision before this repository can claim deterministic headless first-run. All findings are from official project documentation; no live instance was tested.

| App | First-run blocker or decision | Primary source |
| --- | --- | --- |
| netdata | Choose local-only agent versus Cloud claim, required host observation mounts/capabilities, and privacy boundary before a safe Compose plan. | [Netdata Docker installation](https://learn.netdata.cloud/docs/netdata-agent/installation/docker) |
| nginx-proxy-manager | It owns public HTTP/HTTPS ports and certificates; the public edge must have separate DNS/TLS/80/443 approval. Its initial administrator must be provisioned or verified against a pinned release, not left to a GUI race. | [NPM setup guide](https://nginxproxymanager.com/setup/), [advanced configuration](https://nginxproxymanager.com/advanced-config/) |
| node-red | Upstream Docker persists `/data`, but the editor and Admin API are unsecured by default. A pre-start, credential-backed `settings.js` and explicit auth verification are required before publishing beyond loopback. | [Docker](https://nodered.org/docs/getting-started/docker), [security](https://nodered.org/docs/security), [Admin API authentication](https://nodered.org/docs/api/admin/oauth) |
| ntfy | The upstream server is open to everyone by default. A private install needs `auth-file`, `auth-default-access: deny-all`, and a provisioned admin. The current recipe onboarding schema cannot express a no-admin service or safely turn a generated password into ntfy's bcrypt `auth-users` setting. | [Installation](https://docs.ntfy.sh/install/), [configuration](https://docs.ntfy.sh/config/) |
| nzbget | The manifest explicitly marks the image source unknown and lifecycle transitioning. Verify the maintained `nzbgetcom` image, versioned API, default credentials, and safe first-run credential change before pinning a recipe. | [Maintained project](https://github.com/nzbgetcom/nzbget), [documentation](https://nzbget.com/documentation/) |
| ollama | Implemented under the new `no-account` contract: official `ollama/ollama:0.34.1`, loopback-only port 11434, Docker volume at `/models` selected through `OLLAMA_MODELS`, and read-only GET `/api/version` plus GET `/api/tags` verification. No model is pulled or GPU access granted; those remain owner choices and separate acceptance. | [Docker](https://docs.ollama.com/docker), [model path setting](https://docs.ollama.com/faq), [version endpoint](https://github.com/ollama/ollama/blob/main/docs/api.md), [model inventory](https://docs.ollama.com/api/tags), [official image tags](https://hub.docker.com/r/ollama/ollama/tags) |
| open-webui | Official headless admin creation uses `WEBUI_ADMIN_EMAIL` and `WEBUI_ADMIN_PASSWORD` on first startup. The current recipe can pass only a private-file *path* via `fileEnvironment`, not that password value; manual-first-admin leaves a race for the first account. Needs a documented secret injection bridge and selected admin email before a recipe. | [Admin roles and headless creation](https://docs.openwebui.com/features/authentication-access/rbac/roles/), [environment variables](https://docs.openwebui.com/reference/env-configuration/) |
| pangolin | Requires a public host and coordinated edge roles; this conflicts with private/loopback default without separate explicit exposure approval and exact domain/TLS choices. | [Pangolin documentation](https://docs.pangolin.net/) |
| passbolt | Official Docker setup requires SMTP, NTP, public base URL/TLS, database and a first-admin registration link that is finished in the browser extension. This is not a deterministic headless first-account flow under the current adapter interface. | [Passbolt CE Docker installation](https://www.passbolt.com/docs/hosting/install/ce/docker/), [first setup](https://www.passbolt.com/docs/user/quickstart/browser/first-setup/) |
| patchmon | The manifest marks its image unknown. Verify current official server/agent images and agent enrollment contract before pinning or automating it. | [PatchMon documentation](https://docs.patchmon.net/), [source](https://github.com/PatchMon/PatchMon) |

The shared v2 onboarding union now also supports `no-account`; Ollama uses it. The remaining onboarding modes are not generic substitutes for a pre-start configuration file or an app whose password environment variable accepts a value instead of a file path. Adding guessed onboarding declarations would defeat the approval and credential boundary.
