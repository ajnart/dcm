# Repeated catalog constraints and bounded primitives — 2026-09-29

This synthesizes the eight focused app notes and catalog batches A–H. “Candidate” means source-backed catalog material, **not** live deployment or application acceptance. A successful private HTTP probe is narrower still.

| Repeated constraint | Affected apps | Reusable bounded primitive | Current status | Official primary sources |
| --- | --- | --- | --- | --- |
| A service needs an owned configuration file before startup; a static environment list or arbitrary host-path bind is not a reproducible setup. | Node-RED, Vector; also Gatus and Authelia in earlier batches. | Typed, app-owned config rendering with selected non-secret inputs, optional secret references, exact ownership, private permissions, and inspect-before-write/restart rules. | **Missing.** Node-RED and Vector have no recipe or adapter; a health response without auth/topology would mislead. | [Node-RED settings](https://nodered.org/docs/user-guide/runtime/settings-file), [Node-RED security](https://nodered.org/docs/user-guide/runtime/securing-node-red), [Vector configuration](https://vector.dev/docs/reference/configuration/), [Gatus Compose](https://github.com/TwiN/gatus/tree/master/.examples/docker-compose) |
| Upstream consumes a secret as a raw environment value, URL component, or command argument rather than a documented `_FILE` input. | PatchMon, Tracearr; also PhotoPrism, Open WebUI, Seafile, slskd in earlier batches. | Narrow apply-time secret composition/injection, with no payload in catalog JSON, Compose argv, public environment dumps, logs, checkpoints, or plans; verify first-start replay. | **Partial.** Generated private env files now support direct secret values and a typed PostgreSQL URL. PhotoPrism and NZBGet have bounded recipes; slskd has a recipe but no verified setup adapter. Command arguments, other URL formats, and several first-admin flows remain unsupported. | Initial account or API-key creation has a distinct, sometimes browser- or CLI-only flow; a running service is not an administrator handoff. | Node-RED, Syncthing, PatchMon, Tracearr; also Forgejo, Actual, Umami, Navidrome, FreshRSS and others in batches A–H. | App-specific, version-pinned onboarding actions with pre-send checkpoint, exact-owner credential access, lost-response recovery, readback login, and private handoff; add password-only or owned CLI variants only when source-backed. | **Per-app gap.** These eight focused notes add no headless account adapter except Netdata's no-account local API probe. Netdata and Glances full host/container inventory examples also include a socket. | Separately owned, least-privilege Docker API bridge or reviewed remote TLS endpoint: allowlisted operations, exact scope, credentials, network isolation, and independent inventory/read-only acceptance. | **Missing; no casual socket mount.** WUD and Glances remain without recipes. Netdata's candidate deliberately omits Docker access. | [WUD watchers](https://getwud.app/docs/configuration/watchers/), [Portainer install](https://docs.portainer.io/start/install-ce/server/docker/linux), [Dockge Compose](https://github.com/louislam/dockge/blob/master/compose.yaml), [Netdata Docker](https://learn.netdata.cloud/docs/netdata-agent/installation/docker) |
| True host observation or LAN/device discovery needs namespace, privilege, device, or broad host-path authority beyond private bridge publishing. | Glances, Netdata; also Dashdot, Scrypted, Syncthing peer discovery, Pi-hole/Technitium DNS and camera apps. | A distinct host-access/network approval model naming each PID/network mode, capability, device, mount, interface and port; require evidence that the promised host/LAN function works. Netdata has a deliberately **container-only** v2 candidate; its local API success cannot satisfy its host-monitoring role. Syncthing has no recipe pending peer-network and auth decisions. | [Glances Docker](https://glances.readthedocs.io/en/latest/docker.html), [Netdata Docker](https://learn.netdata.cloud/docs/netdata-agent/installation/docker), [Syncthing Docker](https://github.com/syncthing/syncthing/blob/main/README-Docker.md), [Scrypted Compose](https://github.com/koush/scrypted/wiki/Installation:-Docker-Compose-Linux) |
| An HTTP-ready service can still have no functional workload or retained data. | Netdata, Vector, WUD, Syncthing; also Ollama, Prometheus, Loki, VictoriaMetrics, Pi-hole, restic and backup apps. | Typed acceptance beyond setup: selected source/sink or peer, redacted end-to-end probe, exact project restart, and isolated restore where recovery is claimed. Earlier no-account adapters prove only their documented readiness/version endpoint. | [Netdata Docker health target](https://learn.netdata.cloud/docs/netdata-agent/installation/docker), [Vector API](https://vector.dev/docs/reference/api/), [Syncthing REST](https://docs.syncthing.net/rest/), [Prometheus management API](https://prometheus.io/docs/prometheus/latest/management_api/), [restic introduction](https://restic.readthedocs.io/en/stable/010_introduction.html) |

Priority is a design inference, not an implementation claim: first make ordinary config and secret contracts reproducible inside one owned Compose project; model host privileges, Docker authority, public edge, and LAN cutovers as separate approvals. None of these shared primitives should promote an app to managed support without fresh-instance and direct acceptance evidence.
