# PeaNUT v6.0.0 shared setup — 2026-09-29

The pinned [v6.0.0 release](https://github.com/Brandawg93/PeaNUT/releases/tag/v6.0.0) and [README](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/README.md) document `brandawg93/peanut:v6.0.0`, port 8080 (`WEB_PORT=8080`), writable `/config`, and `WEB_USERNAME`/`WEB_PASSWORD` for initial account creation. The container image expects UID/GID 1000:1000 or a selected matching user for its config mount. NUT server/device configuration is separate; PeaNUT alone does not prove UPS connectivity or safe shutdown behavior.

Pinned source inspection at commit `73d5a1ee1caa70092f92a159b73ec8f1d688a4dd` found important differences from the release description:

- [`src/instrumentation.ts`](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/instrumentation.ts) creates the user only when no user exists, using `WEB_USERNAME` and `WEB_PASSWORD`.
- [`src/server/auth-storage.ts`](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/server/auth-storage.ts) defaults `AUTH_FILE_PATH` to relative `config/auth.yaml`; the image works in `/app`, while the documented persistent mount is `/config`. An explicit `AUTH_FILE_PATH=/config/auth.yaml` is required for reliable persistence with that mount.
- [`src/auth.config.ts`](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/auth.config.ts) and [`src/app/api/auth/verify/route.ts`](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/app/api/auth/verify/route.ts) still accept the bootstrap environment credentials on authenticated `/api/v1/*` requests. They are therefore not bootstrap-only in this pinned source; a later UI password change does not revoke them while the environment remains.
- [`src/server/auth-config.ts`](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/server/auth-config.ts) logs `AUTH_SECRET` verbatim whether generated or supplied. Passing a private generated `AUTH_SECRET` through the shared secret environment would leak it to container logs. Omitting it leaves an automatically generated, logged session secret that changes on restart.

`GET /api/ping` is the image's [healthcheck](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/healthcheck.mjs), but it is unauthenticated and proves only reachability. `GET /api/v1/info` is a documented protected route in [pinned source](https://github.com/Brandawg93/PeaNUT/blob/v6.0.0/src/app/api/v1/info/route.ts), and can prove the generated Basic credential when paired with unauthenticated denial; it does not prove NUT or UPS data. There is no separate API key or admin role in this first-user flow.

No shared recipe or headless adapter was published. Although the existing secret-environment primitive can inject `WEB_PASSWORD` and a recipe could set `AUTH_FILE_PATH`, this release's live environment-credential bypass and plaintext secret logging conflict with the repository's private-credential boundary. An upstream fix or a reviewed version with a bootstrap-only path and non-logging session secret is needed before an installable candidate is safe. No Docker pull, first run, NUT connection, or restart acceptance was performed.
