# aria2 shared-Compose first-run gap (2026-09-29)

The [official aria2 manual](https://aria2.github.io/manual/en/html/aria2c.html) documents `--enable-rpc`, `--rpc-secret`, and JSON-RPC `/jsonrpc`. The secret must be supplied as the first RPC method parameter, prefixed with `token:`. `aria2.getVersion` is a read-only verification method; `system.listMethods` is intentionally callable without a token, so it cannot prove authentication. The RPC listener defaults to loopback; `--rpc-listen-all` changes that and needs a separate private host bind.

The [upstream repository](https://github.com/aria2/aria2) publishes source and platform build Dockerfiles, not a verified Linux service image with a documented persistent download/session layout and private token injection contract. A [third-party image publisher](https://github.com/snowdreamtech/aria2) documents a versioned `1.37.0-debian` tag and `/var/lib/aria2/downloads` mount, but its `RPC_HASH` contract is an environment value; when omitted, it generates a token and explicitly tells operators to retrieve it from container logs. Neither path provides deterministic, private generated-token handoff under this catalog's constraints. Its example also publishes RPC and a broad peer-port range without a private bind, which cannot be copied as the default.

The aria2 manual does support an [aria2 configuration file](https://aria2.github.io/manual/en/html/aria2c.html#files), where `rpc-secret` could reside. The new shared `configFiles` primitive creates owner-only static files but cannot interpolate a generated secret; putting a token in its catalog JSON would expose it. The third-party image supports `RPC_HASH`, which the shared secret-environment binding could supply through a private env file, but Docker-inspection users can read the resulting environment. More importantly, the `no-account` onboarding contract requires `privateFiles: []`, and the setup adapter has no typed read/handoff method for a generated RPC token. Calling unauthenticated `system.listMethods` is not a security check. Therefore a recipe plus deterministic authenticated `aria2.getVersion` inspection cannot be published with the current contract. No `recipe.json` or `setup.ts` is added, and support remains discovery.

The smallest common primitive is a token-only onboarding form with one generated private-file ID, a typed adapter read/handoff of that exact token, and a secret-bearing config renderer that writes it to a mode-0600 file without placing it in Compose, argv, or container environment. A separately reviewed fallback could use the image's `RPC_HASH` env contract but must disclose Docker-inspection exposure. Then select and verify a maintained service image, document persistent downloads and session behavior, and check token-required `aria2.getVersion`, denied tokenless calls, download-path ownership, and restart persistence on a fresh instance. Peer ports and VPN fail-closed behavior require separate review. No live deployment or application acceptance was performed.
