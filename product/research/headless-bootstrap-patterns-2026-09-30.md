# Headless first-run patterns — 2026-09-30

This is a source/code map, not live acceptance. A Compose recipe means deployable candidate; a `setup.ts` means a scripted first-run path; neither proves the app worked on a fresh host. Keep app-specific request shapes beside each recipe and the ownership, approval, HTTP, secret, and checkpoint machinery in the shared engine.

| Pattern | Existing example or gap | Reusable primitive | Readiness rule |
| --- | --- | --- | --- |
| Upstream seeds an administrator from a generated secret | Grafana and Open WebUI adapters verify their saved login | Generate and bind an owner-only password, then authenticate against an identity endpoint | The actual saved credential logs in as the intended administrator; an env var or HTTP 200 alone is insufficient. |
| App creates its first owner through HTTP | Immich, Linkwarden, and [Beszel](catalog-beszel-2026-09-30.md) shared adapters | Checkpoint before one-time POST and verify the saved password and owner identity; where registration stays open, close it through an exact owned service revision | Account identity and login must read back. Linkwarden also verifies registration closure; Beszel separately verifies its Hub admin and PocketBase superuser. Restart persistence remains unproven until checked live. |
| App writes an API key to its owned configuration | Sonarr, Radarr, Prowlarr, and Bazarr adapters | Read only the exact service's private config file, save the key mode 0600, then authenticate through the app API | Re-read the app with the saved key; never infer a key from a route name or copy another container's file. |
| App starts with a known shared password | qBittorrent has a pinned temporary-password flow; [Deluge](catalog-deluge-2026-09-30.md) still exposes its public default before rotation | Isolate first boot from peer services, rotate through the documented endpoint, verify the generated password, then join the intended app network | No peer-accessible default-password interval; a loopback host port alone does not isolate Compose peers. |
| App has no administrator or API key | Valkey and Unbound need protocol-specific adapters; Loki, Gatus, and Traefik use the shared `createNoAccountGetAdapter` with app-owned GET paths | Record `no-account` explicitly; reuse the exact-owner/private-GET module when the upstream probe is a single HTTP 200 | Do not fabricate credentials or call reachability an application acceptance test. |
| Upstream CLI takes the first password only in argv | [FreshRSS](catalog-freshrss-2026-09-30.md), [Forgejo](catalog-forgejo-2026-09-30.md), and Beszel's superuser command | Find a documented stdin/file input or prove a private HTTP route; otherwise leave setup pending | Never move a saved secret into process arguments to force a green setup result. |
| API returns a secret only once | Linkwarden and [Firefly III](catalog-firefly-setup-2026-09-30.md) adapters; Forgejo remains a source-backed gap | Persist an attempted checkpoint before the write and save the returned value privately before any next request | A lost response is `needs-inspection`, not permission to create duplicate keys/accounts. |
| App needs an externally chosen authority, privilege, or license | [Seafile](catalog-seafile-2026-09-30.md), [Dashdot](catalog-dashdot-setup-2026-09-30.md), [MinIO/AIStor](catalog-minio-2026-09-30.md), and WUD | Model that choice and its approval in the shared Compose plan, or keep the app discovery/guided | A healthy container without functional URLs, safe Docker authority, or licensed I/O is not configured. |

## Next shared engine changes

1. Reuse the implemented recipe-declared post-first-owner environment transition for apps with an upstream-supported registration gate. The shared owner plans an immutable Compose revision, binds an exact approval to the old/new manifest and service, checkpoints before scoped recreation, and requires saved-login and registration-denial readback afterward. Linkwarden is the first adapter; live first-run and restart acceptance remain open.
2. Add an opt-in isolated bootstrap network for apps with a public initial password. The app should join the common frontend network only after the password is rotated and verified. Deluge is a concrete contract test; it should not be made installable first.
3. Add a token-only private-file/handoff kind if an app needs an RPC bearer secret but no user account. [aria2](catalog-aria2-2026-09-30.md) also needs a maintained, pinned service image before its recipe can ship.
4. For each newly scripted app, prove a fresh-instance first run, interrupted replay, saved-credential login, and restart. Keep direct app acceptance and Homarr board/integration/widget readbacks separate.

The current shared `setupAdapterAvailable` gate checks for an adapter file (except `sharedOwner: false`). Do not add a pending-only `setup.ts`: it makes coverage look better without making setup work. An unresolved app should keep its source-backed recipe candidate and a precise pending reason.
