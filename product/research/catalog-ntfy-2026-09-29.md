# ntfy shared-Compose review — 2026-09-29

The experimental recipe pins `binwiederhier/ntfy:v2.28.0` and follows the [official Docker and Compose guidance](https://docs.ntfy.sh/install/#docker) with container port 80, `serve`, and persistent `/var/lib/ntfy`. Its private host bind remains only a network default, not complete application acceptance. A registry digest and live deployment were not verified.

The [official access-control guidance](https://docs.ntfy.sh/config/#access-control) requires an auth database and `auth-default-access: deny-all` for a private instance; otherwise the documented default is read-write. Its [declarative-user format](https://docs.ntfy.sh/config/#users-via-the-config) is `<username>:<bcrypt-hash>:<role>`. The shared recipe now fixes `NTFY_AUTH_FILE=/var/lib/ntfy/user.db` and `NTFY_AUTH_DEFAULT_ACCESS=deny-all` before first boot. The typed `ntfy-auth-users` binding derives a stable bcrypt hash from the generated owner-only admin password and passes `NTFY_AUTH_USERS` through an owner-only env file. The account is declared as `admin` with the upstream admin role. The source example quotes the bcrypt-bearing env value to preserve literal `$`; the shared primitive verifies the saved hash/password on resume. No raw password appears in Compose or command arguments.

The adjacent setup adapter makes two read-only [topic poll](https://docs.ntfy.sh/subscribe/api/#poll-for-messages) probes on the exact private origin: unauthenticated access must return 401/403, while Basic Auth with the saved administrator must return 200. The [upstream role contract](https://docs.ntfy.sh/config/#users-and-roles) grants an admin access to all topics, and the [API documentation](https://docs.ntfy.sh/subscribe/api/#authentication) documents Basic Auth for protected subscriptions. The adapter reports only administrator authentication and anonymous subscription denial. It creates no topic, publisher, ACL, or token and does not claim an end-to-end notification was delivered. The fixed probe topic must remain unused by other acceptance work.

This is still guided, experimental support. A separate approval and implementation are needed for a least-privilege publisher and exact topic ACLs; [ntfy tokens](https://docs.ntfy.sh/config/#access-tokens) inherit their user's permissions and are not independently topic-scoped. Functional acceptance must prove authorized publish and subscribe readback, denied anonymous publish as well as subscribe, and restart persistence on the exact owned project. No Docker, live HTTP, browser, or restart check was performed here.
