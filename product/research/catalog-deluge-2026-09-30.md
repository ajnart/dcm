# Deluge shared-Compose recheck — 2026-09-30

**Decision:** retain guided support; no `recipe.json` or `setup.ts` was added. The prior [catalog research](catalog-deluge-2026-09-29.md) identified the same blocker, and current image-publisher and Deluge 2.2.0 API documentation still do not close it.

The [LinuxServer image guide](https://docs.linuxserver.io/images/docker-deluge/) documents `lscr.io/linuxserver/deluge`, `/config` and `/downloads`, WebUI port 8112, peer TCP/UDP 6881, and optional thin-client port 58846. It explicitly publishes the shared first-login `admin`/`deluge` credential and recommends changing the password through the WebUI. Its documented environment and file inputs do not include a WebUI password bootstrap. The [Deluge 2.2.0 Web JSON-RPC API](https://deluge.readthedocs.io/en/deluge-2.2.0/reference/webapi.html) and [WebUI package API](https://deluge.readthedocs.io/en/deluge-2.2.0/modules/deluge.ui.web.html) support password login and `auth.change_password`, but only after the WebUI has started.

The versioned Web JSON-RPC reference documents `/json` and password/session methods, but no administrator API-key issuance endpoint. Do not invent an API key or mark a credential handoff as complete on that basis. The image publisher's current Compose example uses the floating `latest` tag; the catalog's fixed `2.2.0-ls381` tag remains a separate image-provenance claim, not proof of a safe password bootstrap.

An `app shared` service joins its reviewed Compose project before its setup adapter runs. A loopback host bind protects against direct remote host access, but does not remove the interval when the shared known password is usable by other containers on that Compose network. Post-start JSON-RPC rotation, even with a saved password and pre-send checkpoint, therefore fails the requested **replace the public default before exposure** boundary. The image publisher does not document an exact pre-start generated-password input, and the current shared recipe/adapter contract has no isolated pre-start network or proven private bootstrap stage. Adding a recipe would make an unrotated default-password service installable in shared Compose; leaving it absent is the safer exact outcome.

A future route must seed a unique password before the WebUI is reachable on the shared network, or provide an owner-bound isolated bootstrap network with no peer access until rotation and saved-password login are verified. Only then should it add the shared `/data` bind (`shareGroup: "media-data"`), a private WebUI publication, separately reviewed inbound peer ports, and replay-safe login/readback. `/data` sharing is storage topology, not VPN egress protection. No VPN claim, tunnel-break check, Docker run, tests, or live login verification was performed.

Recheck limitation: the versioned upstream Web API page was reachable; the image guide and fixed-tag release URL did not return a fresh page through this session's web fetch, so their image-specific statements above rely on the already recorded 2026-09-29/30 source review and should be refreshed before implementation.
