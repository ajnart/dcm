# PhotoPrism shared-Compose candidate — 2026-09-29

The official [Compose guide](https://docs.photoprism.app/getting-started/docker-compose/) supports a single PhotoPrism service with SQLite when MariaDB is omitted, and requires persistent originals and storage paths. This candidate selects that simpler topology, project-owned originals and storage folders, and a loopback port. Existing-library import needs a separate path choice; the shared picker cannot yet adopt an arbitrary originals path. SQLite is a deliberate small-install choice, not a claim of MariaDB-equivalent concurrency. The guide recommends local SSD storage and at least 4 GB of swap for indexing.

The [configuration reference](https://docs.photoprism.app/getting-started/config-options/) documents `PHOTOPRISM_ADMIN_USER` and the first-start-only `PHOTOPRISM_ADMIN_PASSWORD` (8–72 characters). The new `secretEnvironment` primitive can feed the generated alphanumeric password through an owner-only private environment file. It is still a process-environment secret visible to authorized Docker inspectors; it must not appear in plans or logs. A lost first-start response must be resolved by authenticating with the saved password, not by resetting the database. The [official API documentation](https://docs.photoprism.app/developer-guide/api/auth/) identifies `POST /api/v1/session`; the adapter only checks login and does not create or rotate credentials.

The fixed `docker.io/photoprism/photoprism:260728` tag is listed by the [publisher's Docker Hub repository](https://hub.docker.com/r/photoprism/photoprism/tags?name=260728). No digest, fresh deployment, photo upload/index/readback, restart-persistence, backup restore, mobile sync, or Homarr integration has been verified. PhotoPrism supports separate app passwords and API access tokens, but this candidate creates neither. The recipe and adapter are experimental guided support, not managed acceptance.
