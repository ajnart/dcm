# Plex shared setup boundary — 2026-09-29

The official [Plex Docker repository](https://github.com/plexinc/pms-docker/blob/master/README.md) and [bridge Compose template](https://github.com/plexinc/pms-docker/blob/master/docker-compose-bridge.yml.template) show `plexinc/pms-docker`, `/config`, `/transcode`, and `/data`; bridge mode publishes TCP 32400 as the primary server port, plus optional discovery/control ports. The image accepts `TZ`, `PLEX_CLAIM`, and optionally `ADVERTISE_IP`. Its `/config` database needs a filesystem with locking; media can be mounted read-only when the owner does not want Plex to write into it. The `public` and `beta` tags install or update a server binary at container start, so they are not immutable application pins. No reviewed immutable current image tag was established here.

`PLEX_CLAIM` is a short-lived token the owner obtains from [plex.tv/claim](https://www.plex.tv/claim). The official image uses it to obtain a server token for the owner's external Plex account; it is ignored when the server is already signed in. [Plex installation guidance](https://support.plex.tv/articles/200288586-installation/) directs local first setup at `http://127.0.0.1:32400/web`. A claim token is not a local admin password, a newly generated API key, or proof of ownership. Remote access and UDP discovery need separate approval and cannot be inferred from a private HTTP 200.

The current v2 recipe supports generated private files and narrow generated-password onboarding kinds. Its only `external-first-admin` kind names a selected Jellyfin provider, not a Plex account. It has no one-time owner-supplied private claim-token input, no exact-token expiry/replay handling, and no source-backed readback proving the resulting server belongs to that owner while keeping the server token out of ordinary status. Putting `PLEX_CLAIM` in a non-secret input or committing it to catalog JSON would violate the credential boundary. Therefore no recipe or `setup.ts` was added; Plex remains guided.

An eventual route needs a private claim-token handoff at exact apply, a reviewed pinned image, owner-bound claim verification, and checks after restart. Local playback, selected library paths, transcoding, remote access, and account-entitled features are separate acceptance claims. No Docker pull, claim, Plex account action, library scan, or live verification was performed.
