# Bazarr shared recipe — 2026-09-29

The LinuxServer [Bazarr image documentation](https://docs.linuxserver.io/images/docker-bazarr/) publishes port 6767, `/config`, optional media mounts, PUID/PGID/TZ, and `unless-stopped`. Its application setup section says the web UI's setup parameters must be completed before saving configuration. The [tagged image registry](https://github.com/linuxserver/docker-bazarr/pkgs/container/bazarr/versions) lists stable `version-v1.6.0`; this recipe pins that tag and binds its port only to loopback. The owner-selected `/data` bind shares Sonarr/Radarr's `media-data` path and is writable because subtitle files are created beside media. No provider, Arr API credential, or media root is inferred.

The [v1.6.0 configuration source](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/config.py#L175-L180) generates `auth.apikey` from 16 random bytes and defaults `auth.type` to no authentication, with empty username and password. It also creates `config.yaml` before onboarding and marks `BAZARR_CONFIGURED=1` when that file exists ([source](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/config.py#L460-L470)); the settings save marks the database configured only after writing ([source](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/app/config.py#L822-L835)). Thus an HTTP 200 or config-file presence is not admin acceptance. The [pinned settings endpoint](https://github.com/morpheus65535/bazarr/blob/v1.6.0/bazarr/api/system/settings.py#L19-L39) is authenticated for both reads and writes. The image documentation exposes no credential bootstrap environment variable and requires web-UI setup. The current shared setup secret interface has readers for Servarr `config.xml`, SABnzbd INI, and qBittorrent logs, not Bazarr's generated YAML key. A whole-config container read would unnecessarily expose other settings; this scope cannot add a narrow owner-checked reader. No pinned, owner-scoped API-key extraction and auth-update/replay contract was established; an unauthenticated settings write or config-file guess would be unsafe. There is no Bazarr-specific adapter here: `app shared setup` must report pending, and its generated password is only a private handoff for manual Forms configuration. A future headless adapter needs exact-owner API-key extraction, a source-pinned auth update, checkpoint-before-write, and new-login/API readback. Sonarr/Radarr and provider wiring are outside this boundary.

This is a source-level recipe candidate only. No Docker pull, fresh-profile installation, browser onboarding, restart, or subtitle write has been performed.
