# Private canonical origins: pinned restriction audit

Checked 2026-10-03; Pangolin 1.24.0, Passbolt API 5.16.0, NetBird 0.80.0 (embedded Dex a163de3129e5), Stalwart 0.16.24. Source research only: no runtime, Docker, credentials, browser, provider writes, tests or CI. No installability/acceptance promotion. All 94 catalog apps remain in scope; administration-only and local-only modes are not full-purpose acceptance.

## Decision

**No reviewed app inherently requires a public DNS zone/public ingress merely to serve its canonical HTTPS identity.** Passbolt and Stalwart can advertise a high-port private origin now. NetBird's runtime preserves high ports, but its full purpose requires an origin reachable by real peers, protocol-aware routing and direct approved STUN. Pangolin's dashboard supports a high port, **but its resource authentication/links assume default HTTPS port**: relaxing its compiler alone is not a full-purpose fix.

| App | `https://APP.localhost:4443` | Actual smallest change |
| --- | --- | --- |
| Passbolt | Server canonical URL supported; local compiler already permits it. Encrypted-client enrollment remains a different gate. | No origin-validator relaxation. Derive `APP_FULL_BASE_URL` from the saved reviewed route; preserve forwarded HTTPS and original Host including port. |
| Stalwart | Management origin supported; local recipe/headless checks already permit it. Default advertised JMAP URL otherwise loses the port. | Add source-backed non-secret `STALWART_PUBLIC_URL=reviewedOrigin` to recipe and include it in approval/fingerprint. Verify JMAP discovery after recovery closure. |
| NetBird | Runtime/OIDC support the authority; local compiler and login contract currently reject it. Not reachable by remote peers under ordinary localhost resolution. | Relax both app-local no-port/`.localhost` exclusions only for a reviewed supported route; render `server.exposedAddress` using parsed `hostname` + explicit effective port, not `${origin}:443`. Full use needs routable private DNS/TLS and the protocol routes below. |
| Pangolin | Dashboard schema/cookie support it; not complete resource behavior. | Dashboard-only relaxation is safe to research but earns no full-purpose credit. Add private default-443 resource routes and hostname-only base domain, or change/prove upstream resource-port semantics. Do not put ports in `base_domain`/`fullDomain`. |

## Pinned evidence

### Pangolin: dashboard restriction is local; resource-port assumption is real

[Config schema](https://github.com/fosrl/pangolin/blob/1.24.0/server/lib/readConfigFile.ts#L10-L60) treats `dashboard_url` as URL and `base_domain` as nonempty string; there is no localhost or port prohibition there. [Dashboard session cookie](https://github.com/fosrl/pangolin/blob/1.24.0/server/auth/sessions/app.ts#L21-L30) derives Domain with `new URL(dashboard_url).hostname`, not authority; [serialization](https://github.com/fosrl/pangolin/blob/1.24.0/server/auth/sessions/app.ts#L178-L194) sets Secure/HttpOnly/SameSite=Lax. Thus the port does not contaminate the cookie Domain. [CSRF middleware](https://github.com/fosrl/pangolin/blob/1.24.0/server/middlewares/csrfProtection.ts) requires the fixed CSRF header, not a public hostname.

But [resource token authentication](https://github.com/fosrl/pangolin/blob/1.24.0/server/routers/resource/authWithAccessToken.ts#L151-L165) constructs `redirectUrl` from scheme + `resource.fullDomain`, with no external port. [Traefik generation](https://github.com/fosrl/pangolin/blob/1.24.0/server/lib/traefik/getTraefikConfig.ts#L341-L347) creates `redirectScheme` with scheme only; [host rules](https://github.com/fosrl/pangolin/blob/1.24.0/server/lib/traefik/rule.ts) use hostname matching. [Domain input](https://github.com/fosrl/pangolin/blob/1.24.0/server/routers/domain/createOrgDomain.ts#L26-L35) uses [hostname-only schema](https://github.com/fosrl/pangolin/blob/1.24.0/server/lib/schemas.ts#L39-L46): no supported resource-port field was established. Inserting `:4443` into a domain is not a sourced fix. For normal SSL resource redirects, an externally reachable private **443** route is the smallest safe pinned topology; it need not be public-facing.

Local seam: `apps/pangolin/configuration.ts` rejects `origin.port`, dashboard `.localhost`, and resource-base `.localhost`; these are stricter than dashboard schema. The local-only config remains explicitly local-only, not tunnel acceptance. Full tunneling still needs its Gerbil/network/client evidence. App-owned dynamic Traefik/Badger routing is separate from a generic static dashboard proxy.

### Passbolt: exact configured URL, not no-port FQDN

[5.16.0 configuration](https://github.com/passbolt/passbolt_api/blob/v5.16.0/config/app.default.php#L39-L60) sources `App.fullBaseUrl` from `APP_FULL_BASE_URL`. [URL healthcheck](https://github.com/passbolt/passbolt_api/blob/v5.16.0/src/Service/Healthcheck/Core/ValidFullBaseUrlCoreHealthcheck.php) accepts HTTP/HTTPS prefixes, not a public-zone/default-port rule. [Full-base middleware](https://github.com/passbolt/passbolt_api/blob/v5.16.0/src/Middleware/AssertFullBaseUrlMiddleware.php) enforces a nonempty configured string. [SSL middleware](https://github.com/passbolt/passbolt_api/blob/v5.16.0/src/Middleware/SslForceMiddleware.php) redirects using original `HTTP_HOST`; preserving `:4443` and HTTPS detection avoids loops/wrong redirects. [JWT challenge](https://github.com/passbolt/passbolt_api/blob/v5.16.0/plugins/PassboltCe/JwtAuthentication/src/Authenticator/JwtArmoredChallengeService.php#L37-L42) binds its domain to the configured absolute router URL, so client/server canonical URL must agree exactly. Session configuration uses Lax cookies, not a public-DNS gate.

Local `deriveCanonicalEnvironment` already accepts `passbolt.localhost:4443`; registration/enrollment parser binds the exact same origin. [Official CE Docker installation](https://www.passbolt.com/docs/hosting/install/ce/docker/) documents self-signed HTTPS. None of this proves browser-free OpenPGP enrollment, encrypted resource roundtrip, SMTP delivery or owner key custody.

### NetBird: runtime ports work; installer defaults are not runtime constraints

[Combined runtime](https://github.com/netbirdio/netbird/blob/v0.80.0/combined/cmd/config.go#L262-L281) parses exposed address into protocol, hostname and host:port using `net.SplitHostPort`; relay/signal/client defaults retain host:port. [Example](https://github.com/netbirdio/netbird/blob/v0.80.0/combined/config.yaml.example) explicitly describes `protocol://hostname:port`. [Installer](https://github.com/netbirdio/netbird/blob/v0.80.0/infrastructure_files/getting-started.sh#L103-L125) accepts a hostname without port and defaults HTTPS to 443: that constrains this installer, not generated configuration.

[NetBird go.mod](https://github.com/netbirdio/netbird/blob/v0.80.0/go.mod) pins Dex a163de3129e5. [Dex server](https://github.com/netbirdio/dex/blob/a163de3129e5/server/server.go#L263-L267) parses issuer URL; `absURL` preserves its authority. [Redirect validation](https://github.com/netbirdio/dex/blob/a163de3129e5/server/oauth2.go#L715-L726) accepts exact registered redirect URIs, including ports. [Session cookie](https://github.com/netbirdio/dex/blob/a163de3129e5/server/session.go#L117-L147) is host-only (no Domain), Secure based on issuer HTTPS, and scoped to issuer path. No public/no-port cookie requirement found.

Local `configuration.ts` and `login-contract.ts` both reject ports. Fix both, including exposed-address rendering, not only one. Full peer service needs HTTP `/api/` + `/oauth2/`, upgraded WebSocket `/relay` + `/ws-proxy/`, native HTTP/2 gRPC routed to h2c upstream `/signalexchange.SignalExchange/` + `/management.ManagementService/`, and separately approved UDP3478. [Official reverse-proxy contract](https://docs.netbird.io/selfhosted/external-reverse-proxy) requires these distinct paths/protocols. `*.localhost` is only suitable for same-host callers or explicitly proved routing; remote peer onboarding cannot assume it reaches the server.

### Stalwart: use the actual 0.16 environment override

[Pinned environment implementation](https://github.com/stalwartlabs/stalwart/blob/v0.16.24/crates/store/src/registry/local.rs#L56-L67) reads `STALWART_PUBLIC_URL`, trims trailing slash and retains port; fallback `STALWART_HTTPS_PORT` exists. [HTTP config](https://github.com/stalwartlabs/stalwart/blob/v0.16.24/crates/common/src/config/network.rs#L441-L450) uses registry public URL before default `https://server_name`; [JMAP session](https://github.com/stalwartlabs/stalwart/blob/v0.16.24/crates/http/src/request.rs#L229-L245) uses this advertised base, not forwarded Host. Therefore proxy transport alone is insufficient: set this env explicitly. Do not invent legacy `http.url` or new Bootstrap/set URL properties. [Official Docker docs](https://stalw.art/docs/install/platform/docker/) explicitly document high-port public URL override.

`recipe.ts` and `headless.ts` already accept `.localhost` + HTTPS port. This unlocks accurate private administration/discovery, not complete mail-server purpose. Mail listeners, mailbox/delivery, client trust/access and DNS prerequisites must remain separately named. A management-only listener policy cannot close full Stalwart acceptance.

## Smallest common feature and sequencing

1. Reuse existing reviewed private HTTPS for Passbolt and Stalwart. Wire canonical-origin derivation and Stalwart's explicit advertised URL first; no common public-FQDN feature is needed for these origins.
2. Add one explicit **private canonical origin** capability to the existing TLS owner: reviewed non-localhost private hostname/certificate, exact private bind/address and optionally standard TCP443, with collision/ownership checks, trust and client-route verification. Public ingress/DNS/ACME must remain separately approved. Do not silently turn highport into443 or acquire host-wide authority.
3. Express app-owned protocol routing through that same owner: Pangolin dashboard/resource/Badger dynamic routes; NetBird split dashboard/control-plane HTTP, WebSocket and h2c. Standard443 resource route is needed for pinned Pangolin's generated resource URLs; NetBird highport is technically possible when all peers and issuer URLs consistently reach it.
4. Relax only disproven app-local checks, preserving exact-origin normalization, scoped TLS proof, cookie boundaries, explicit app inputs and approval fingerprints. Add no guessed config fields. Full-purpose acceptance still requires each app's actual client/workload and restart evidence; this report supplies none.
