## Proven useful boundary

The adapter is **post-manual-bootstrap**, not automatic first-owner creation.
The owner must complete the wizard with `admin` and this project's generated
password. [Login](https://dev.emby.media/reference/RestAPI/UserService/postUsersAuthenticatebyname.html)
and [user readback](https://dev.emby.media/reference/RestAPI/UserService/getUsersById.html)
prove the exact enabled password-configured administrator; authenticated
[configuration](https://dev.emby.media/reference/RestAPI/ConfigurationService/getSystemConfiguration.html)
independently proves `IsStartupWizardCompleted`. AuthenticationResult's
[User property](https://dev.emby.media/reference/pluginapi/MediaBrowser.Controller.Authentication.AuthenticationResult.html)
is an object, despite the REST table's array annotation.

Persistent key creation uses the vendor's administrator-only
[POST Auth/Keys?App=label](https://dev.emby.media/reference/RestAPI/SessionsService/postAuthKeys.html),
with before-send checkpoint and exact project label. The
[inventory route](https://dev.emby.media/reference/RestAPI/SessionsService/getAuthKeys.html)
supports pagination but omits response schema; the pinned shipped client
establishes Items/AppName/AccessToken and the vendor
[AuthenticationInfo](https://dev.emby.media/reference/pluginapi/MediaBrowser.Controller.Security.AuthenticationInfo.html)
documents IsActive. The adapter conservatively requires a complete
TotalRecordCount/Items inventory, rejects duplicate/inactive/unowned keys,
captures the unique attempted key privately, then proves it through protected
reads with [X-Emby-Token](https://dev.emby.media/doc/restapi/API-Key-Authentication.html).
Anonymous configuration must be denied, preventing permissive pre-wizard
routes from masquerading as token proof. A session bearer is never exported as
the durable API key.

Resume uses the same private session and approval payload. A lost create
response is reconciled against inventory without sending creation again.
Failed verification after capture resumes the same saved key. A missing
attempted key, changed identity, truncated inventory, duplicate label or
uncheckpointed key stops for inspection.

## Exact unresolved first-owner gap

[Public system info](https://dev.emby.media/reference/RestAPI/SystemService/getSystemInfoPublic.html)
still has no wizard flag. Authenticated configuration cannot establish an
untouched state before first login. The vendor API index has no startup
reference, and the pinned client does not establish whether GET Startup/User
creates state or prove pre-wizard authorization. Its Name/Password and bodyless
completion requests are therefore recorded evidence, not permission to script
them. Startup configuration payloads remain unproven and unused.

The recipe stays manual-first-admin and support stays discovery/T2. Adapter
readiness means the manually established administrator and captured key were
verified; it does not assert automatic bootstrap, media indexing/playback,
Homarr integration, image-user mount readability, or restart persistence.
