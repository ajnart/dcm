# Monitoring and mail gaps — 2026-10-03

Source-only recheck of the existing 2026-09-30 research against the current recipe schema and setup types. No recipes or readiness adapters are published for these four apps: a reachable empty dashboard or bootstrap wizard would not fulfill their catalog role. Pinned tags remain planning facts, not registry-resolved digests or live acceptance.

| App / pin | Exact remaining boundary | Required authority and acceptance |
| --- | --- | --- |
| Dash. `6.3.4` | [Official Compose](https://getdashdot.com/docs/installation/docker-compose) requires privileged mode and read-only host `/` at `/mnt/host`. Recipes cannot express the privilege; selected-path validation rejects `/`. | Separate reviewed host privilege and root-visibility approval. Its documented [API](https://getdashdot.com/docs/integration/api) can support no-account probing later, but must also prove accurate host inventory/metrics. No fabricated administrator or API key. |
| WUD `9.1.0` | [Watchers](https://getwud.app/docs/configuration/watchers/) default to the Docker socket. The [remote/proxy contract](https://getwud.app/docs/configuration/watchers/remote-tls/) needs a reviewed read-only API boundary and WUD-only network, absent from ordinary shared recipes. | Exact socket/proxy ownership and read-operation allowlist approval; deny mutations and never publish proxy API. Verify selected inventory, update detection, authentication/anonymous denial and restart persistence. `:ro` is not Docker API authorization. |
| Frigate `0.18.0` | [Starter](https://docs.frigate.video/guides/getting_started/) requires configurable camera/storage choices and captures generated credentials from logs. Private config and cache tmpfs now exist, but generic exact-start log capture and the authenticated HTTPS origin do not. [Pinned auth source](https://raw.githubusercontent.com/blakeblackshear/frigate/v0.18.0/frigate/api/auth.py) defines login/profile; no request body is invented. | Approve exact camera streams, retention and any devices; no device/privilege default. | Stalwart `v0.16.23` | [Bootstrap](https://stalw.art/docs/configuration/bootstrap-mode/) starts no mail services and replaces the temporary administrator with a permanent one. [Declarative deployment](https://stalw.art/docs/configuration/declarative-deployments/) needs `config.json`, recovery-mode CLI apply, then restart without **both** recovery variables. The single non-secret post-account environment transition cannot perform this lifecycle. | Bind reviewed hostname/domain and permanent account; remove recovery credentials and verify their rejection plus HTTPS login. Separate public listener/DNS/TLS/outbound approval; inbound/outbound mail round trips, anti-abuse and restore evidence remain required. |

## Isolated validation plans (not executed)

- Dash.: a disposable host with separately approved privilege/root mount; compare API inventory with inspected host facts, then repeat after scoped restart.
- WUD: disposable Docker host with an exact read-only proxy/network plan; prove denied writes, watched inventory and known update detection without enabling update triggers.
- Frigate: an owner-approved synthetic camera and isolated storage; no devices until separately approved; capture/rotate/login, record/read back a segment, then verify restart persistence. First define trusted HTTPS or an explicitly reviewed upstream-supported private transport policy.
- Stalwart: owned test hostname/domain and isolated mail sandbox; staged recovery removal, permanent account verification, DNS/TLS and mail protocol round trips only after their exact approvals. No production ports or public delivery default.

Validation in this change is limited to JSON parsing and bounded catalog/schema validation. No Docker, browser, installer, unit/e2e suite, fresh-account or restart checks were run. Support is unchanged: three guided entries, Stalwart discovery-only. Unblocking these entries requires shared capability work, not app-specific CLI routers or schema-only support promotion.
