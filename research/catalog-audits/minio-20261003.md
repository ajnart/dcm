# MinIO shared setup audit — 2026-10-03

Decision: preserve discovery support; no static recipe or authentication setup
adapter is published. An app-local pure compiler now produces a reviewed AIStor
recipe proposal only from explicit `edition: "aistor-licensed"` and a non-default
root identifier. It binds the verified digest and recipe fingerprint, prepares
generated password plus owner-license declarations, and explicitly remains
not installable/setup-pending/key-not-created. The remaining integration is in
[setup-contract.md](../../.agents/skills/self-host/workflows/selfhost/references/catalog/apps/minio/setup-contract.md).

The find-docs skill was used: Context7 library resolution selected
`/websites/min_io_aistor`, followed by separate container-license and root-file
documentation queries (three commands total). Live official pages and the public
Quay tag API were then checked. No private file, container or API was inspected.

The [community repository](https://github.com/minio/minio) remains archived.
[AIStor](https://docs.min.io/aistor/installation/container/install/) is a separate
licensed choice, even for Free. Its current versioned non-FIPS image tag and
registry index digest match the earlier storage/mail audit; image availability
is not the missing primitive.

The previous command-path-only recommendation was too broad.
[Core settings](https://docs.min.io/aistor/reference/aistor-server/settings/core/)
explicitly documents `MINIO_LICENSE` as a file path. A sourced
`fileEnvironment` `format: "file-path"` consumer is the minimal proposal:
reuse existing owner-file import and read-only mounting without a made-up
`MINIO_LICENSE_FILE` or `file:` URI. It must coexist with root onboarding.
No shared schema/engine/registry change was authorized in this app-owned pass.

Generated root password binding exists. A generated root login/access-key
identifier needs an explicit private reference/handoff, or an approved
non-default literal login choice. Archived community entrypoint behavior is not
proof for proprietary AIStor. Signed S3 authentication, scoped key-pair capture
and replay, active-license write/read proof and restart acceptance remain
unimplemented. [License behavior](https://docs.min.io/aistor/operations/licenses/)
makes unauthenticated health or administrative reachability insufficient.

Validation: focused JSON parsing and manifest/source assertions, changed-script
Bun builds, the app-local compiler fixture (including common recipe validation
with fixture-only explicitly derived image metadata), and diff hygiene. No broad
test suite, Docker deployment, credential access, enrollment, CI, commit or push.
