## Corrections to earlier blocker lists

1. **Dashdot need not read the entire host root.** [Pinned FAQ](https://raw.githubusercontent.com/MauriceNino/dashdot/v6.3.4/apps/docs/content/docs/faq.mdx) permits selected OS-release, network-namespace and drive mounts. [Pinned setup](https://raw.githubusercontent.com/MauriceNino/dashdot/v6.3.4/apps/server/src/setup.ts) explains the harder part: Docker networking can execute `nsenter` and mount sysfs. [Pinned entrypoint](https://raw.githubusercontent.com/MauriceNino/dashdot/v6.3.4/apps/server/src/index.ts) calls networking/OS setup before widget loading. Therefore “remove privileged and hide network” is not yet a proven permission-safe profile. Use the narrower mount contract, then prove the actual minimum grant; do not begin with blanket `/` visibility.
2. **Passbolt image is no longer unknown.** Read-only [publisher tag metadata](https://hub.docker.com/v2/repositories/passbolt/passbolt/tags/5.16.0-1-ce) returned index `sha256:dc7298c2847e406154beea5c4c82062828e0b1690d1d9869b2dbeae6f6e70bfc`, Linux amd64/arm64/arm. AMD64 manifest: `sha256:25245e0ec87cda69d914fea1850582031c166e0462af599bb9091e2d2149a28c`; ARM64: `sha256:638b0736732f3a745027f343c644cfc5eebc9ad70adee7379055239710f0bb84`. Re-resolve the chosen platform at approval; metadata is not live acceptance. [Docker guide](https://www.passbolt.com/docs/hosting/install/ce/docker/) explicitly allows self-signed HTTPS, requires SMTP/NTP and describes a registration link. [First setup](https://www.passbolt.com/docs/user/quickstart/browser/first-setup/) requires extension/key/passphrase/recovery custody; [API introduction](https://www.passbolt.com/docs/development/getting-started/) establishes OpenPGP client identity, not a password-only bootstrap shortcut.
3. **Pangolin has a useful no-authority local role.** [Without tunneling](https://docs.pangolin.net/self-host/advanced/without-tunneling) documents the local authentication/reverse-proxy outcome. [1.24.0 Compose](https://raw.githubusercontent.com/fosrl/pangolin/1.24.0/install/config/docker-compose.yml) conditionally excludes Gerbil and gives Traefik normal ports. Remap those to private/high host ports through the shared ingress owner; don't assume public 80/443 is necessary. [Config](https://docs.pangolin.net/self-host/advanced/config-file) describes site-type restrictions and server secret. [Admin CLI](https://docs.pangolin.net/self-host/advanced/container-cli-tool) exposes password argv, so it is not the private-password route. Bootstrap log capture remains unresolved.
4. **Cloudflare local configuration is an alternative to remote config, not offline/no-provider access.** [Local-management configuration](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/) supports private WARP routing and explicit ingress. [Tunnel permissions](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/tunnel-permissions/) distinguishes tunnel-only JSON from account-wide `cert.pem`; the runtime should not receive the latter. Cloud policy/route inspection and intended-client denial remain necessary even when origins are local. Existing `host-selected` runtime user rendering exists, but is not evidence that distroless cloudflared supports every selected UID; prove the exact image before using it as the readability fix.

## Implementation order and exact seams

1. **Private canonical-origin/TLS apply + typed bootstrap-secret capture**: reuse `shared-private-https.ts`, selected-service resolution, generated private config, CAS checkpoints and private stdout. This unlocks useful no-Gerbil Pangolin and deployable Passbolt preparation without host-control relaxation. Do not introduce broad log reads: bind one pinned bootstrap format, owned service, first-start interval and private capture destination. Passbolt needs its already reviewed enrollment-link parser, not a password-capture alias. Encrypted-client acceptance is a subsequent distinct gate.
2. **Verified pre-start external connector authority**: extend existing connector/schema/file-import primitives, not another Compose owner. Bind exact account/tunnel, local or remote config fingerprint, selected upstream target and access policy; inspect/recheck before activation. Private runtime secret readability needs an exact-image contract. Cloudflare local-management is a narrower supported option, not a bypass of provider approval.
3. **Approved startup-external-writes + digest-only image selection**: a small reusable plan field for precisely disclosed startup registration/telemetry/workload effects, persisted into apply/restart approval. Warrior then needs only its app recipe/adapter and explicit content/project budgets, not host privileges. No auto-selected project by default.
4. **Bounded host-observation authority**: Dashdot's official reduced mount list is the starting scope. Prove minimal capability/namespace requirements; do not encode unconditional privileged + `/` as the only design. A partial CPU/RAM mode can be investigated first, visibly narrower than full host/dashboard acceptance.
5. **Docker/SSH host-management authority + app-event transport**: finish adoption and freshness/identity verification after the existing `docker-api-authority.ts` approved-intent planner. Dockge additionally needs coherent stack paths and pinned Socket.IO setup; Coolify needs SSH and scheduled-job/proxy ownership. These grants cannot be inferred from generic APP approval and do not preserve one-project-only mutation authority unless separately scoped/disclosed. A deliberately selected dedicated management host is a sane opt-in, not an unsafe app exception.
6. **Overlay authority**: exact TUN/capability/network consumer profile, controller membership and live peer evidence for ZeroTier. Keep unknown official image provenance explicit. Do not replace the catalog app with libzt or a different VPN just to eliminate the gate.

Acceptance for every path must separately record purpose-complete behavior, credentials/client identity where applicable, persistence after exact-owner restart and native Homarr/widget proof where claimed. Health or HTTP 200 alone never closes those gates.
