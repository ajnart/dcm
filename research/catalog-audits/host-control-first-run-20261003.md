Implemented the useful app-side Gluetun control bootstrap fragment, not a
disconnected manager or health-only VPN recipe. Reused
[management review](management-headless-remaining-20261003.md),

## Implemented boundary

`apps/gluetun/control.ts` declares one generated 32-byte hex control key and one
TOML `privateConfigs` fragment for `/gluetun/auth/config.toml`. The fixed role
allows only status, public-IP, and forwarded-port GETs; no restarting GET or PUT.
It uses existing owner-only config preparation rather than handling secret
files itself. The pinned [role defaults](https://github.com/passteque/gluetun/blob/v3.41.3/internal/server/middlewares/auth/settings.go)
retain public access when roles are absent; a nonempty explicit role list replaces
those defaults. [Middleware](https://github.com/passteque/gluetun/blob/v3.41.3/internal/server/middlewares/auth/middleware.go)
rejects unassigned routes and failed authentication with 401.
[API-key authentication](https://github.com/passteque/gluetun/blob/v3.41.3/internal/server/middlewares/auth/apikey.go)
uses `X-API-Key`; do not substitute the moving autodocs' Bearer example.

`verifyGluetunControl` accepts only the existing exact-owner read-only HTTP
surface plus the privately supplied generated key. It requires anonymous 401,
authenticated 200, and a recognized status body. It returns no key and expressly
leaves readiness, write-authorization, downloader namespace, tunnel-break, and
restart claims false. It performs no potentially successful control mutation to
test denial. No `recipe.json` or discoverable `setup.ts` was added.

Exact remaining common seam: a VPN-owned reviewed apply capability must bind
provider/protocol and owner credential references, explicit NET_ADMIN and TUN,
same-owner downloader namespace without fallback ports/routes, and private
gateway control publication. It can reuse this config fragment and verifier;
the source-pinned image must be able to read the private mount. No existing
ordinary recipe grants these powers. A recorded running-downloader tunnel-break
IP **and DNS** failure/restoration remains mandatory, separately from control
authentication. [Pinned installation](https://github.com/passteque/gluetun/blob/v3.41.3/README.md),
[namespace attachment](https://github.com/qdm12/gluetun-wiki/blob/main/setup/connect-a-container-to-gluetun.md).
