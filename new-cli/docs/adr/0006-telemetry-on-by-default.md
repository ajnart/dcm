# Telemetry is on by default, anonymous, public, and off with one environment variable

We shape the CLI around what people actually install and where Setup actually breaks, and agents fixing a failure have no channel back to us. So the CLI sends Telemetry to the project's PostHog through `https://hog.ajnart.dev`: a random install ID, version, OS and architecture, command names, App and Recipe IDs, the Access choice, failed step IDs, and errors as PostHog `$exception` events. It never sends host names, file paths, inputs, secrets, App data or error text that could carry them. PostHog sees each request's public IP and derives a country from it; whether the raw IP is kept is a PostHog project setting, stated on the public dashboard. `self-host feedback` lets an agent send a report on purpose, after the person agrees; the CLI masks every known secret in it before sending. Telemetry is announced on first run and in Onboarding, the collected data is published on a public dashboard, and it is off with `SELF_HOST_NO_TELEMETRY=1` or `DO_NOT_TRACK=1`, and always off in CI and development builds. On by default was chosen over opt-in because opt-in data from a self-hosting audience is too sparse to steer by; the never-sent list and the public dashboard are what make that acceptable, so widening either needs a new ADR.
